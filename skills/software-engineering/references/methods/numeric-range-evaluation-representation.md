## 1. 先固定需要保持的结果

数值审查要确认每一步能否保留要求的数量含义；条件审查要确认哪些表达式会被求值、访问什么、改变什么；表示替换要确认调用者仍得到同一结果。这三个问题可以沿同一项小改动检查。已有单位、范围和简单条件说明足够时，保留简短判断，不必把每项改动扩成完整算法教材。

先写清输入、成功与失败输出、允许修改的状态和独立预期，再挑选候选。[第8节](#8-来源与原创推导分工)列出这些检查原则的书名、版本、章/节与使用条件；下面的材料目录、数值上限、舍入规范、伪代码、证明和成本都是本文原创工程适配。它们只作静态推导，没有运行示例、Skill 或真实案例。

本方法使用明确规定的语言无关模型。实际应用前另查目标语言、版本、算子、类型转换和容器的官方语义；本模型中的范围、短路和固定成本不代表任何平台的默认行为。

## 2. 定义材料报价与独立预期

### 2.1 输入、输出与状态

材料目录是本次调用独占持有的不可变记录序列，每条为 `(id,p,active)`。`id` 是材料编号，`p` 是每千克整数分单价，`active` 决定是否可报价。记录顺序只用于保存目录；请求顺序决定输出顺序。

| 对象 | 本题固定要求 |
|---|---|
| 目录 | 最多64条；编号是0至255整数且各不相同；单价为0至999999整数分/千克；active必须是布尔值 |
| 请求 | 最多4096项；每项(id,m,d)；m为0至99999整数克；d为0至2500整数基点；1基点=1/10000 |
| 输入拒绝 | 先校验整批请求；缺字段、非整数、越界或非有限数拒绝整批，不产生部分输出；格式解析和数值校验均为正常路径 |
| 一项输出 | 不存在为Missing(id)；存在且停用为Inactive(id)；可报价为Quoted(id,cents) |
| 顺序和重复 | 每项有效请求恰有一个同序输出；同编号出现两次就产生两项输出；金额不跨项汇总 |
| 计算状态 | 不改目录和请求，不读隐藏环境，不保存或发送结果；输出附目录与规则版本 |
| 目录更新 | 新完整目录可以增删材料、改价、改启用状态或调序；校验并构建成功后在两批请求之间替换当前根；失败保留旧目录 |

输入及可达记录由调用方保证在校验、复制和一批查询期间不变；没有并发、重入回调和外部 I/O。构建的新目录归当前调用所有，成功后不外传可写别名。输出是值，不能让调用者借结果改写目录。真实平台的内存分配失败若可能发生，应在对外输出前完成必要准备；本题计数模型只分析容量已经保证、操作成功的路径，不能从它推出内存不足时的部分输出保证。

### 2.2 用业务数量定义正确金额

先在数学上的精确有理数中定义金额：

`x = (p 分/千克) × (m 克) ÷ (1000 克/千克) × (10000-d)/10000`。

最终 `cents` 是离 x 最近的非负整数；正好处于两个整数中点时，选其中偶数。只在形成这一整数分结果时舍入，上限为100000000分。每条请求单独计算，不能先把克数取整到千克，也不能先将折扣前金额取整。

独立预期来自这个最近整数关系，而非待检查的计算函数。以 `p=12345,m=2500,d=1250` 为例，2500克为2.5千克，折扣前为30862.5分，保留87.5%后为27004.6875分。它距27005为0.3125，距27004为0.6875，所以预期是27005。此推导先于后面的除法候选固定。

| 输入(p,m,d) | 精确金额与独立预期 | 能区分的错误 |
|---|---|---|
| (1,500,0) | 0.5分，取偶数0 | 中点总向上会得到1 |
| (3,500,0) | 1.5分，取偶数2 | 直接截断会得到1 |
| (5,500,0) | 2.5分，取偶数2 | 中点总向上会得到3 |
| p=0或m=0，其余在范围内 | 0分 | 零值不得被误当缺失或默认值 |
| (999999,99999,0) | 99998900.001分，取99998900 | 最终范围满足，但某些中间表示不足 |

这些点用于区分所列错误。全部输入的范围与舍入正确性由第3节的推导承担，不能用几个结果替代一般证明。

## 3. 从单位推到每个中间值

### 3.1 明确运算和转换发生在哪里

本题定义 `U50` 为0至1125899906842623（2^50−1）的整数，`U27` 为0至134217727，反例中的 `U32` 为0至4294967295。每个运算精确计算后检查结果范围，越界立即失败，不回绕、不饱和。输入先按数学整数验证，再逐个转成U50；扩宽发生在乘法之前。这里的类型名称是题设定义，不是语言类型名。

`DIV` 和 `MOD` 对非负整数 N、正整数 D 满足唯一关系 `N=qD+r, 0≤r<D`。以下是候选步骤的静态定义：

1. 确认 p、m、d 在上述范围并分别转换到U50；10000和1000也作为U50常量。
2. 计算 `f=10000-d`、`a=p×m`、`N=a×f`、`D=1000×10000`。
3. 计算 `q=N DIV D`、`r=N MOD D`。如果 `2r<D` 取q；如果 `2r>D` 取q+1；如果相等，q偶数取q，q奇数取q+1。
4. 确认结果不超过100000000分，然后转为U27整数分。越界时返回明确失败，输入保持原样，不以近似值或默认零代替。

| 步骤 | 含义与单位 | 全部有效输入的范围及表示 |
|---|---|---|
| f | 折扣后保留份数，每10000份 | 7500至10000，U50 |
| a=p×m | 分×克/千克；尚未除1000 | 0至99998900001，U50 |
| N=a×f | 金额的整数分子；带有克/千克及每10000份尺度 | 0至999989000010000，U50 |
| D=1000×10000 | 换算克/千克及折扣尺度的常量分母 | 10000000，严格为正，U50 |
| q，r | q为整数分，r/D为不足一分的部分 | q≤99998900；0≤r≤9999999，U50 |
| 2r及q+1 | 与半分比较及可能的进位 | 2r≤19999998；q+1≤99998901，U50 |
| 输出 | 舍入后的整数分 | 保守上界99998901小于100000000且小于U27上限；转换有依据 |

上界来自非负因子的逐项上界：`999999×99999=99998900001`，再乘10000得999989000010000，小于U50上限。因此连最大的中间乘积都能精确表示。该证明依赖原输入范围；业务上调数量或单价时必须重算，不能只保留最终字段类型。

单位关系给出 `x=N/D`。由 `N=qD+r` 可知最近整数只能是q或q+1，二者距离分别为r/D和1−r/D；比较2r与D恰好选出较近者，中点分支按q的奇偶选偶数。于是步骤3满足独立的最近整数定义，误差绝对值至多0.5分。这里没有近似比较容差，不能把书中示例阈值移来改变舍入边界。

### 3.2 正向路径与失效路径

主输入逐步得到 `f=8750`、`a=30862500`、`N=270046875000`、`D=10000000`。于是 `q=27004,r=6875000`；`2r=13750000>D`，返回27005分，与独立预期相同。输入并未改变。三项中点输入都得到r=5000000；q分别为0、1、2，按奇偶返回0、2、2。

最终结果能够装入输出字段，不说明先前操作安全。上界输入的正确结果99998900能装入U27，但 `p×m=99998900001` 超过U32上限。先在U32相乘，再把乘积转U50，会在转换发生前失败。把乘法外面加转换无法改变这个求值顺序。改用浮点也必须重新证明精确性，本题不能仅凭数量级可表示就接受它。

改变除法位置同样可能改变结果：

| 错误候选 | 主输入的静态结果 | 为什么不满足要求 |
|---|---|---|
| 先做整数 `m DIV 1000` | 2500克先成2千克；12345×2×0.875=21603.75，最终21604 | 在质量单位转换处丢失0.5千克 |
| 先把折扣前金额取最近偶数整数 | 30862.5先成30862；乘0.875得27004.25，最终27004 | 提前舍入改变最终最近整数 |
| 先在U32算p×m，最后再扩宽 | 上界输入中间失败，尽管正确最终值有界 | 扩宽时点太晚 |

若平台不提供能精确容纳这些中间值的表示，可以评审分解计算或精确十进制/大整数候选，也可以在需求允许时缩小输入范围。每种候选都要给出自己的范围和结果证明；本文没有证明那些替代算法。无法满足精确结果或平台语义未知时，停止该候选的实施结论。

## 4. 比较具体条件改写

### 4.1 真值、访问与状态分别观察

单项预览的可选入口有私有整数 `tickets`。`reservePreview()` 在tickets大于0时减1并返回true，否则保持0并返回false。调用方只允许在记录存在且启用后调用它一次；此状态步骤与第2节纯报价计算是两个明确接口。以下分支均从各自初态重新开始，不把上一分支的tickets遗留给下一分支。

定义 `AND` 从左到右短路。原式为：

`r≠Missing AND r.active AND reservePreview()`。

| 初态 | 原式的实际求值 | 返回与最终状态 |
|---|---|---|
| r=Missing，tickets=1 | 只判断存在性 | false，tickets=1，预留调用0次 |
| r存在但inactive，tickets=1 | 判断存在性，再读active=false | false，tickets=1，预留调用0次 |
| r存在且active，tickets=1 | 两检查为true，再预留一次 | true，tickets=0，预留调用1次 |
| r存在且active，tickets=0 | 两检查为true，再尝试预留一次 | false，tickets=0，预留调用1次 |

改成 `r.active AND r≠Missing AND reservePreview()` 后，Missing分支先访问不存在的字段，按本模型立即发生访问错误；原式返回false。这不是布尔交换律错误，而是r.active并非在所有输入上都有定义。

改成 `reservePreview() AND r≠Missing AND r.active` 后，从inactive、tickets=1开始，先消耗到0，再返回false。原式同样返回false，却保留tickets=1且没有预留调用。只对照最终布尔值会漏掉这个差异。Missing分支也会先消耗票数，即使重排后的存在性检查仍能保护字段访问。

### 4.2 保持求值关系的正向改写

安全候选先判断Missing并返回false，再读取active；inactive时返回false；最后只调用一次reservePreview并返回其结果。它逐分支对应上表的调用顺序、次数、访问前提与最终状态。用一个惰性调用的命名函数封装“存在且启用”也可以，但函数必须在内部保留同样的保护顺序。提前计算 `isActive=r.active` 再判断存在性不满足这个条件。

只有当待交换的条件在全部相关输入上都有定义、不抛异常、无可观察副作用、对同一稳定状态求值且调用次序没有接口含义时，才能用布尔真值等价支持重排；仍须保留分支返回含义。会计数、消费、记录日志或依赖时机的调用不属于这类纯条件。必要状态动作放在明确步骤中，其失败结果仍要保留。

本题只有顺序局部状态。若tickets、目录或其可达对象可能被并发访问，完整检查与修改必须按既有共享状态方法确定同一保护范围；不能先查询“还有票”，离开保护后再独立扣减。查询与命令分离有助于理解接口，不自动产生原子性或持久化保证。求值保护与隐藏修改原则分别见第8节的 Code Complete 19.1 和 Clean Code 3.7–3.8；将真值与状态变化一并检查是两者的综合，本节完整状态表为本文原创推导。

## 5. 用两个具体表示完成同一查询

### 5.1 先固定表示以外的结果

目录C0为 `[(7,12345,true),(2,3,true),(9,800,false)]`。请求编号序列为 `[2,7,2,8,9]`，对应克数为 `[500,2500,500,500,500]`，折扣为 `[0,1250,0,0,0]`。按照唯一编号关系和第2节金额定义，结果应为：

`[Quoted(2,2),Quoted(7,27005),Quoted(2,2),Missing(8),Inactive(9)]`。

此预期来自“对每个请求位置找唯一同编号记录”的关系定义及已登记金额，不由任何查找候选产生。返回集合、按目录顺序输出或去重编号都会改变结果；把Missing当作单价0也会错误地产生Quoted。

### 5.2 共同校验与两个候选的操作

先检查目录条数不超过64及结构完整。逐字段解码为明确标量；不能让字符串、缺失字段或非有限数潜入本题的整数计算。为校验编号唯一性，创建长度U=256的seen表并逐格清零；依次读取每条记录，检查id上下界、p上下界与active类型。只有id范围通过后才访问seen[id]；已出现则拒绝整个新目录，否则置true并复制该记录到私有向量。成功后释放seen。失败时丢弃本次临时向量和seen，旧目录保持。

A保留这份私有向量。对每个请求按原序处理：读请求id；从向量第一条依次读取记录并比较id；第一项匹配即返回该不可变记录，走到末尾则返回Missing；把该结果写入本请求位置。然后按共同的active及数值步骤形成预览值。它不排序、不去重，也不改目录。

A的查找不变量是：开始考察第i条前，前i−1条均不匹配。匹配时编号唯一性保证这就是关系定义中的记录；扫描完n条仍无匹配则关系中不存在该编号。每步增加已考察条数，最多n步终止。外层严格按请求位置前进，因此输出次数、顺序和重复请求都保持。

B保留同一私有向量，另建256格直接索引T。先将每格写为Missing，再逐条读向量记录，令T[record.id]引用该完整不可变记录。对每个请求按原序读取id、读取T[id]并写入本请求位置，再执行相同的共同步骤。这里是有界整数直接寻址，没有排序或哈希分布假设。

B的构建不变量是：处理前i条后，这些编号的格恰好引用各自对应记录，其他格仍为Missing。唯一性防止后条覆盖前条；每格由编号选择，与目录位置无关。处理n条后每个范围内编号恰好符合唯一身份关系，因此一次格读取得到与A相同的结果。请求id已校验，不能把范围检查移到访问T之后。

### 5.3 更新与错误表示

完整新目录C1为 `[(9,800,true),(7,12346,true),(8,1,true)]`。先独立推导同一请求的结果：

`[Missing(2),Quoted(7,27007),Missing(2),Quoted(8,0),Quoted(9,400)]`。

其中7的精确金额为27006.875分；8的0.5分取偶数0；9为800×0.5=400分。A重新校验并复制C1，B还必须用C1重新构造全新的T。成功后一起替换该目录版本的向量和索引；本题在两批请求之间完成替换，旧记录和旧索引不会与新版本混用。

若B只覆盖C1中出现的格而不清空/重建，T[2]会残留旧记录；若把向量位置当编号，则重排C1后对应错误；若只更新单价而忘记active，9仍会返回Inactive。这些错误都不能用“查询更少”接受。提交包含重复id=7的新目录时，两候选均在共同校验中拒绝，不能选择第一条、最后一条或累加它们。

调用者若要使用跨目录、跨类型或跨存储的身份，先扩充真实身份定义；0至255只在本题单份目录内唯一。这里的记录引用不表示数据库中已提交或始终最新，序列位置更不等于持久身份。成本与结果含义须一并检查，是第8节所列 The Pragmatic Programmer 第32节与 Clean Code 3.8 原则的综合；本节身份、表示不变量、更新和反例为本文原创推导。

## 6. 从操作推导成本与选择

### 6.1 计数对象及不包含的成本

本节固定的一个单位是一次指定记录/表格访问或字段关系检查：固定大小记录读取、完整记录复制写、单格读写、标量检查、一次请求读取或一次结果写入，各计1。记录有三个固定标量字段；这里把其复制算一次，是虚构计数约定。循环控制、局部变量、分配元数据和共同数值计算另记，不计入这个特定指标。它不能被称为全部指令数、字节数、延迟或吞吐。

目录结构/解码、请求整批校验、active判断、报价计算及必要输出格式处理都仍要执行。这些相同工作另加共同成本G；比较查找表示时不能删除它们。下面的10000明确命名为“每期目录构造/查找计数额度”，只约束表内W，不能承诺整个服务预算；真实时间须按工作负载与测量方法另取证。

整批请求数值校验另有q次请求读取，以及每项id、m、d各两个上下界检查，共7q。字段完整性、解码、整数类型和非有限值检查另记C_decode(q)；目录条数/结构校验、循环控制、分配元数据、active与金额步骤及最终结果处理记G_other。因此完整工作至少要写成 `W+7q+C_decode(q)+G_other`，本题没有给后两项实际成本，也没有总服务成本保证。查找时重新读取请求的操作已经在W中，不能用前面的读取抵销。

设n为本期目录条数，q为本次构建后至下次完整替换前的查询项数，v_j为A第j项实际读过的记录数。存在项位于第k条时v_j=k；缺失项v_j=n；空目录时v_j=0。不能用n替代所有输入的实际访问数而宣称平均成本。

| 操作 | 从实际步骤相加 | 有效路径单位数 |
|---|---|---|
| 共同校验及复制 | U个seen清零写；每条1记录读、5字段检查、1 seen读、1 seen写、1记录复制写 | U+9n |
| A附加构建 | 直接使用上述私有向量 | 0 |
| B附加构建 | U个Missing写；n记录读；n索引格写 | U+2n |
| A一次查询 | 1请求读；v_j记录读及v_j编号比较；1结果写 | 2v_j+2 |
| B一次查询 | 1请求读；1索引格读；1结果写 | 3 |

共同校验中的“seen读到true”或字段越界会提前结束，这些是拒绝新目录的路径，不能作为完成相同有效工作时的收益。条件分支判断使用刚读出的布尔值，不另产生一次格读取；循环控制按上面的排除项另记。

所以每个有效目录时期的本指标为：

- A：`W_A=U+9n+Σ(2v_j+2)`
- B：`W_B=(U+9n)+(U+2n)+3q=2U+11n+3q`

多次更新应逐时期相加，每次使用本期n和q。一次完整替换即使只改了一个价格，也按本候选重新校验、复制和重建，不假装已有增量维护算法。分配元数据等成本若对候选不同，应单独比较；本公式没有给它们赋零的现实结论。

### 6.2 空间与峰值也从表示推导

本题的目录引擎计量用逻辑槽：每条记录三个槽，seen或索引一格一个槽。请求、输出缓冲由调用者拥有，固定数量局部变量也单列；这里的资源限制明确只针对这些目录/临时表槽。初次构建时，A和B的峰值均为 `3n+U`：共同校验用seen，B在seen释放后才创建等长索引。稳定时A为3n，B为3n+U。

替换时旧目录必须保留到新构建成功，不能只报告稳定空间。A峰值为 `3n_old+3n_new+U`。B先保留旧向量和旧索引，再为新目录使用seen或新索引，峰值为 `3n_old+U+3n_new+U`。旧索引不在新构建前拆除，否则构建失败无法按要求继续使用旧版本。实际字节、对象头、对齐、回收时机和分配失败须按平台验证；不能将一个逻辑槽直接写成一个字节。

### 6.3 用同一指标作有边界的决定

先比较U=256、n=8、全部查询都缺失的已定输入形状。共同校验为328；A每查一次18；B附加构建272、每查一次3。

| 本期q | A本指标 | B本指标 | 在本题内的选择 |
|---|---|---|---|
| 1 | 328+18=346 | 328+272+3=603 | 保留A；一次查询无法偿还索引初始化 |
| 64 | 328+64×18=1480 | 328+272+64×3=792 | 若空间满足且本指标值得降低，可改B |

一般的缺失查询比较为 `q(2n−1)>U+2n` 时B单位数更低；n=8时为15q>272，最小整数q为19。若查询总命中首条，则A每项为4、B为3，需q>272才偿还构建；“查19次就用索引”不适用于这个形状。空目录n=0时A每项为2，B每项为3且还有U初始化，B在本指标没有优势。这里的增长结论从实际访问数得出，没有用循环层数或几次计时拟合证明。

频繁更新可能推翻热查询收益。64项查询共用一次目录时B为792；若每次查询前都换目录，64个n=8、q=1的时期分别重建，则A为64×346=22144、B为64×603=38592。两组工作不同，不能把前一组的收益用于后一组，也不能跳过新目录更新来保持缓存快。

最后固定n_old=n_new=64、U=256、q=512、全部缺失，允许每期目录构造/查找计数额度至多10000。共同校验832，A每项130，所以A为67392；B附加构建384，所以B为2752。A替换峰值640槽，B为896槽。

- 峰值限制为1024槽时，B满足896槽及2752单位，A超过本指标限制；在本题内选择B
- 峰值限制为640槽时，B不满足替换峰值；A可以保留，但每期最坏查询数必须满足 `832+130q≤10000`，即q≤70。q=70为9932，q=71为10062
- 本题允许开始前拒绝超过预算的请求，因此640槽条件下应明确限制每期受理量；q≤70只证明W满足额度，请求校验及其他必要工作的资源还须另核。把512项悄悄拆成若干批不会消除同一期总量；若要求同一期完整处理512项，就必须调整资源或评审其他候选，本方法没有已经满足要求的方案

这些都是虚构约束下的静态选择，没有证明真实运行更快。对于U远大于n、编号不能稳定界定、记录包含变长字段或更新方式不同的任务，应重新推导表示、成本和接口范围。

## 7. 检查应用条件并留下有限结论

小改动可以只留下输入范围、中间值表、一个区分错误的反例及选定表示的理由。风险增加时补充可复查依据，仍围绕当前问题。

| 实际变化 | 应继续取得的依据 |
|---|---|
| 输入上限、负数或精度要求变化 | 重算每个中间范围；定义负数舍入及新误差允许量；本文非负证明不自动延伸 |
| 改用具体语言、算子或库 | 固定版本并查官方转换、运算、溢出、除法、求值顺序、索引和所有权语义 |
| 状态被其他执行者访问 | 使用共享状态方法检查完整检查/修改、可见性、别名和失败边界 |
| 单位跨API、存储或消息边界变化 | 使用迁移方法逐项检查格式版本、读取/修改路径、旧值可表示性和恢复 |
| 查询混合、更新频率或资源限制变化 | 按实际步骤重计构建、查询、更新、峰值空间；真实收益另用性能方法测量 |
| 需要证明实际行为 | 保留独立预期及观察范围，在另获授权的执行阶段按目标平台检查；静态一致不登记为执行通过 |
