## 1. 从需要保住的结果开始

派生结果是从权威资料按明确转换得到的索引、缓存、组列表、统计结果或其他表示。它帮助完成特定查询，不是因为用了流处理就自动正确。重建指从有依据的输入重新构造指定表示；对账指在同一输入范围上核对结果与独立预期，并解释差异。这三个过程都要说明最终用户可以观察到什么。来源D25、D29、D33、D36、D42、D45。

在选择工具前，定义以下事实。没有必要的数据可以保持待核，但要说明它阻止哪项保证。

| 必要输入 | 需要作出的判断 |
| --- | --- |
| 查询形态、结果含义与必要观察范围 | 是否需要独立表示，哪些结果必须包含已接受变化 |
| 权威记录及全部更新入口 | 谁决定事实和顺序，是否存在绕过来源的直接写入 |
| 初始范围、变化含义及来源身份 | 从什么状态开始，怎样处理新增、覆盖、增量和删除 |
| 故障后可取得的材料与期限 | 输入是否还在，状态、规则和进度怎样对应 |
| 可接受滞后、错误及权限 | 哪些查询可等待或明确返回旧结果，哪些效果必须停止 |

原创拼贴符号目录有三个对象，只需按身份读取标签；题设给定一个现有存储已经满足查询、观察和恢复要求。保留它是可行选择。只有搜索、不同读取形态、隔离负载或其他具体要求尚未满足，才比较新增索引或独立派生存储；不为不存在的规模增加组件。这个题设没有证明真实产品的容量。来源D33、D36；适配A01。

是否接受暂时冲突再作补偿，是业务结果选择；它不等于允许丢失关键事实。需要改变约束时，按实际代价和权限决定，不能把补偿视为任何场景都可接受。来源D43。

评审任务交付有条件的设计与缺少的证据；实施任务在已有授权内进行必要变化。需要受控暂停、替换结果或清理历史时，先区分本次任务已经授权的动作和仅供选择的方案。调用方法不会扩大权限。当前产品的保证按实际版本、配置和写入路径取证。

## 2. 确定权威记录与更新路径

### 2.1 两次双写成功也可能留下相反结果

目录对象A@1的标签起初为“叶”。记录系统决定先执行u改为“波”，再执行v改为“星”；独立派生存储却先收到v再收到u。两个写入都成功，前者最终为“星”，后者为“波”。另一次w可能只写成功记录系统；x的提交响应丢失时，调用者还可能无法确定是否提交。三个问题分别是顺序分歧、部分失败和结果未知。来源D08、D26；适配A01。

给w增加重试没有回答u和v应怎样排序。给x换一个操作身份也可能把同一意图执行两次。先选择谁接受事实、决定冲突和顺序，再说明全部派生变化如何从它取得。每种候选都要覆盖提交、发布、交付、应用、恢复和查询可见，不能以名称代替保证。

| 更新路径 | 在什么条件下可比较 | 必须继续承担的责任 |
| --- | --- | --- |
| 同一存储内维护索引或结果 | 所需事实、结果和约束确实受同一提交保护，读取满足原要求 | 核对实际隔离、错误处理及查询含义；不能把外部动作算入本地提交 |
| 跨资源共同提交 | 全部必要参与者支持相应提交协议，决定持久保留并能够恢复 | 准备不等于完成；响应未知、阻塞和恢复均有证据，实际观察保证另证 |
| 事实与持久待发送记录共同保存 | 接受事实与输出意图不可分离地提交，恢复者能发现尚未交接的工作 | 发送可能重复；下游处理效果、顺序、历史保留及结果观察仍需保护 |
| 从权威记录捕获变化 | 捕获范围覆盖全部有关提交，并能追溯初始状态和后续变化 | 核对快照切点、保留、删除和变化格式；异步交付不默认提供读己之写 |
| 以接受的业务事件作为权威输入 | 命令校验和已接受事实分开，输入含义及保存责任明确 | 事件如何形成状态、是否需要全部历史，以及新版本重算的规则必须定义 |

待发送记录可以与事实放在同一行，也可以是同一事务中的另一项；单独再写一次不满足共同保存。发送前退出、发送响应丢失、下游处理后确认丢失分别推导恢复，具体复用[原子效果与恢复方法](message-atomic-effect-recovery.md#2-比较提交次序与较小方案)。来源D09、D12、D13、D22、D27、D39；适配A01。

如果派生存储还允许直接写入，就要解释这些修改如何成为权威变化、参与冲突决定并传播至其他表示。无法解释时，应把这项来源责任列为缺口，不能继续声称结果完全从权威输入派生。

## 3. 定义输入含义、效果与连续进度

### 3.1 同一位置不是完整的输入身份

输入记录至少要能识别所属来源历史、分区或相应排序范围、实际续读位置、对象及生命周期、变化类型和必要版本。需要去重时，身份还要与固定输入或可核对的完整引用绑定。同一个位置在另一份历史中可以指向另一条变化；对象公共标识重用后也不能继承旧生命周期的更新。来源D04、D05、D20、D23、D24、D39；适配A01、A03。

连续进度表示指定来源和范围中，截止某个已核实位置的必要输入都已完成约定处理。它不是见过的最大数字。真实日志可以存在未用于提交记录的编号；怎样确认下一条必要输入，应依据实际可续读位置、范围完整性及来源协议，不能一概要求数字相邻。

| 记录含义 | 可以证明什么 | 不能单独证明什么 |
| --- | --- | --- |
| 接收到输入 | 某条资料到达了当前处理者 | 输入持久保存或已应用 |
| 稳定保存 | 相应资料按已核实条件能够恢复 | 派生结果已经更新 |
| 已应用 | 指定版本的处理效果按约定保存 | 查询入口已经看到相同结果 |
| 查询可见 | 相应结果已进入指定查询路径 | 所有分区和其他依赖均已覆盖 |
| 连续覆盖 | 声明范围内没有未完成的必要输入 | 外部通知完成或任意全局共同顺序 |

这些含义可以合并保存，但不能合并为模糊的“已同步”。多级索引或缓存有额外的可见过程时，应保存与具体派生版本、范围及位置对应的证据，再满足调用者要求。来源D05、D15、D21、D27、D34、D37、D42；适配A03。

### 3.2 按变化含义选择处理办法

完整状态记录可以表达“对象版本2现在在橙组”；增量记录可以表达“从青组减1、给橙组加1”。前者重复覆盖相同值可能不改变结果，后者重复执行会多次改变数量。即使是覆盖，旧版本迟到也可能退回新状态，因此还需要顺序或对象版本保护。来源D11、D12、D19、D23；适配A01、A02。

本例A@1在青组、B@1在橙组，数量均为1。d1把A@1移至橙组，一次效果得到青0、橙2；重复执行同一增量会变成青-1、橙3。若结果保存而去重未保存，恢复后可能重复；若进度先保存而效果未保存，恢复后可能漏做。天然幂等、操作身份和连续进度解决的责任不同。

派生输出若参与唯一性或跨对象业务约束，需要核对约束实际生效的时点及共同保护范围。某个分区内顺序处理，不自动保护跨分区约束；相关推导复用[业务不变量与事务方法](invariants-aggregates-transactions.md)。来源D41。

需要本地共同保存时，可采用以下最小串行方案，前提是目标资源确实提供相应共同提交、原子冲突保护和持久恢复能力。它是工程适配，不是所有数据库的默认行为：

1. 读取该派生版本的源历史、完整进度、处理版本和当前执行资格，取得来源确认的下一条必要输入。
2. 在实际提交中保护共享进度及资格，确认没有其他处理者已推进或更换此状态。仅读取一个旧快照而不产生相应互斥或冲突保护不够。
3. 校验输入身份和固定内容；已处理的同一输入复用其已保存决定，身份相同而内容不同则停止核对来源。
4. 依据已有对象贡献和当前变化，计算应移除与应增加的贡献。把对象状态、受影响结果、去重依据和该条连续进度共同保存；涉及多个记录时实际共同保护范围必须覆盖它们。
5. 明确中止则这些写入均未发生，从原进度恢复。提交结果未知时读取该资源的已提交决定，保持原身份核查；不凭超时补写更大位置。
6. 接手确认或下一次处理只根据已取得的共同保存证据继续。结果另有查询可见阶段时，继续取得那一阶段的证据。

本例位置按题设连续编号。当进度为4却先收到6时，不能将6记为连续完成，也不能顺便漏掉5。先取得并正确处理5，再继续6、7。并行处理可以采用另一套完成集合与连续进度归并方式，但须证明共享进度、遗漏、重做和旧处理者竞争，不能只把逐对象唯一保护当成全部分区进度保护。复用[连续消费位置方法](message-atomic-effect-recovery.md#5-连续消费位置不能越过空缺)。来源D05、D22、D24、D34；适配A01。

输入无法解码、必要位置不可读取或历史身份改变时，停止依赖完整覆盖的推进，保留资料、已知进度和具体缺口。若变化仅用来触发重新查询，还要解释查询对应的版本、遗漏期间最终状态、删除及聚合贡献；当前查无记录不自动说明输入从未发生。

## 4. 让一致快照与后续日志衔接

### 4.1 建立共同依据，不能拼一个看似合理的位置

一致快照S4含权威状态截止位置4的全部有关对象：A@1在青组、B@1在橙组。后续变化5将A移至橙组，6删除B，7创建青组C。完整应用后的独立结果是青组[C@1]、橙组[A@1]，数量均为1。若漏掉5，青组可能是[A@1,C@1]、橙组为空；看到7或总对象仍为2，都不能证明正确。来源D06、D10、D32；适配A02。

快照必须说明覆盖的来源、过滤条件、对象范围、规则版本和切点。日志切点必须与快照里的权威事实相对应。扫描开始时记下一个编号，但扫描期间读到不同时间的对象，不能由此宣称整次扫描都对应那个编号。目录文件存在和复制结束也没有这种含义。

### 4.2 在线衔接与受控暂停分别取得证据

在线构造要核实底层快照和变化捕获实际提供什么，不将一个产品功能名当完整协议。常见的设计责任包括：

1. 在可能丢失后续变化前建立捕获与保留范围，确保初始化期间需要的输入能够取得。
2. 取得一致快照及相应来源历史、分区范围和已核实切点；记录哪些变化已包含，哪些必须从日志补入。
3. 在隔离输出构造基线，并把完整材料清单、处理版本和相应输入位置绑定。基线未完整核查时不能把切点当成可恢复完成记录。
4. 依据来源的续读规则追赶后续输入，解释快照和日志之间可能的重叠、重复与缺口。重叠部分不能再次执行增量；来源变化和对象版本仍须相符。
5. 核查并发新增、移动、删除及连接依赖，记录连续覆盖与查询可见范围，再判断能否满足请求或启用要求。

具体平台若不能证明快照切点、捕获起点或并发变化没有遗漏，在线方案保持待验证。不能用“先读全表再订阅”补出已经丢失的交界。来源D09、D10、D19、D32；适配A02。

任务允许受控暂停且代价可接受时，可以比较较小的基线方案：暂停相应权威修改，确认在途写入已经结束或中止，保留必要日志；读取停止变化的完整状态与对应切点；核对并稳定保存材料及绑定；恢复修改后从已核实后继输入继续。暂停新请求不等于旧写入已停止。涉及多来源共同状态时，相应来源及依赖也要纳入保护，不能只暂停其中一张表。若不允许暂停，应继续验证在线方案及其依赖，不改变原业务要求来假装完成。

### 4.3 恢复基线与进度不能错配

新输出构造期间可保存构造进展，但“扫到某处”和“基线已经完整可用”是不同状态。只有完整材料、格式、规则及覆盖范围已核对并取得稳定保存证据，才能形成与这份基线对应的可恢复记录。恢复者必须核对材料与记录，不能取一个新进度去配旧状态。

从只应用至7的状态却使用进度10，再从11继续，就会跳过8至10。文件恢复成功也不会补出这些变化。缺少材料时，先取得可靠输入或新的有依据基线；不能通过修改位置把缺失变成完成。来源D10、D25、D32；适配A02。

压缩日志仅在记录能完整替换此前状态、覆盖范围完整且删除含义已核实时，才可作为当前状态构造材料。遍历压缩文件不自动得到同一时刻的一致快照；从旧输出上重放最新值也可能留下没有删除记录的旧对象。比较从空的隔离输出重建或可靠快照方案，核查完整对象范围与交界。增量事实、历史版本关联和恢复旧副本不能套用只保留每键最新值的概括。来源D11、D12、D20；适配A02。

## 5. 把删除与旧贡献纳入恢复

维护组列表和数量时，删除不是简单地让对象行消失。A从青组移至橙组，需要移除青组中的旧贡献并增加橙组贡献；B被删除，还要从橙组列表和数量移除B。先定义对象在每项派生结果中的贡献，以及重建时能从哪里取得它。来源D19、D23；适配A01、A02。

| 变化 | 正确处理需要什么 | 容易遗漏的结果 |
| --- | --- | --- |
| 更新改变组或关联字段 | 旧贡献、新贡献及对应对象版本，或足以重算的可靠状态 | 新组增加了，旧组仍残留 |
| 对象删除 | 生命周期、删除版本、相关贡献及全部必要派生位置 | 源对象消失，索引、数量或缓存仍可见 |
| 旧输入迟到 | 当前生命周期及已保存版本或顺序判断 | 被删除对象重新出现，或新对象被旧删除误删 |
| 公共标识再次使用 | 将A@1与A@2区分的稳定依据 | 旧历史被当成新对象的输入 |
| 旧快照恢复 | 当前删除或撤回依据，以及恢复后仍可能出现的旧输入 | 已删除内容重新对外暴露 |

本例A@1删除后，公共标识A对应新生命周期A@2。A@1的版本2更新和版本3删除均不能更改A@2；版本数字要在正确生命周期内解释。若数据中没有足以区分的依据，不能猜测某条历史输入属于新对象。

用完整状态覆盖更新结果时，应确认旧贡献已经移除且新状态与所声明版本相符。用增量时，需要固定输入、重复保护及贡献保存。按当前权威状态重新查询时，必须解释删除、竞态与聚合所需旧资料；不能直接把旧值重新插入。局部版本与删除判断复用[混合读写与历史消息方法](mixed-version-data-migration.md#53-历史消息能解码还要判断能否应用)，其局部前提仍须满足。

删除标记需要保留多久，取决于迟到输入、消费者基线、旧快照和允许重放的全部路径。若只从新的完整范围构造空输出，没有旧对象可残留，这是不同于恢复含旧对象备份的条件。清除标记、销毁资料、禁止访问及保留审计依据也可能承担不同责任，按明确要求决定；本文不提供通用法律结论。来源D11、D16、D19、D44；适配A02。

## 6. 固定重放依赖和观察范围

### 6.1 同一日志不保证同一结果

记录决定结果的输入范围、代码、格式、转换规则、配置，以及外部关联资料的必要版本或可复查内容。引用一个会变化的“当前”别名，不等于保留了历史依赖。处理必须使用哪个时间点，属于结果含义，不能由重放执行时的机器时钟暗中决定。来源D17、D18、D20、D29、D35、D45；适配A03。

本例目录位置7含橙组A@1与青组C@1。规则r1允许两组，r2仅允许橙组。G1定义使用r1，结果应为[A@1,C@1]；G2定义使用r2，结果应为[A@1]。重算G1时查询当前r2，会改变原结果含义。确需采用新规则，应明确构造G2及其输入范围，不把它冒充G1原样恢复。

输入业务时间、处理时间和接收时间分别记录用途。窗口或关联允许迟到资料时，定义是否更正、需要保留哪些状态、怎样通知下游结果改变；超时不证明输入已全部到齐。原书时钟估计有延迟与偏移稳定的前提，不能当通用校时算法。

### 6.2 多来源的位置要与依赖关系一起解释

对每个必要输入保存来源历史、分区、切点和已应用范围，再说明它们怎样共同满足本次转换。A的位置7和R的位置100不能按数值比较新旧；一份最快消费者进度也不能代表所有输入。若关联按事件引用的r1计算，要证明r1仍可取得；若查询要求当前r2，则相应当前派生结果也要完成并可见。来源D04、D19、D20、D28、D38；适配A03。

一组位置可以表示“这些输入各处理到哪里”，但不自动证明它们构成共同一致的状态。任务确实需要因果依赖或共同快照时，记录并核对相应关系、完整范围及协议依据；无法取得时保留待验证，不能用全部位置都很大作为替代。

请求q要求G2、A的完整位置7及规则r2。处理者仅收到r2、或保存r2却仍提供按r1构造的查询，都不满足q。实际查询入口必须取得匹配版本和全部必要依赖的可见证据。允许旧结果的任务可明确返回其版本与已知范围；严格要求则等待满足、拒绝依赖该保证的请求或按原约定处理，不能默默降低要求。具体读取保证复用[读取观察与数据分布方法](data-reading-distribution.md)。来源D15、D27、D37、D42；适配A03。

历史转换规则与当前访问或撤回控制也要分开。用r1重建历史含义，不表示可以忽略后来删除、撤回或资格限制。对外开放之前取得可靠的当前控制，再判断哪些结果可提供。

## 7. 在隔离位置构造新派生版本

为新版本定义独立身份与输出位置，绑定权威输入范围、快照和后继日志、格式、规则及配置。记录构造中、已完成基线、追赶中、待核查、可按条件服务等实际状态；不要求照搬这些名字，但恢复者必须能区分它们代表的证据。来源D07、D25、D30、D31、D32；适配A04。

1. 明确新结果要保留原含义还是采用新规则。选择足以重建该含义的完整输入材料，保留当前旧结果的实际用途与限制。
2. 在不会污染活动结果的位置构造基线，绑定材料与版本；期间失败可从仍有依据的进展恢复，或丢弃未开放的新输出重新构造。
3. 按第3至6节的变化含义和完整进度追赶。缺失输入、规则或格式依赖时保留未完成状态，先解决材料问题。
4. 在明确输入范围上对账，继续追踪此后变化；只有对账范围、追赶范围及请求要求相符，才能评价服务资格。
5. 按第9节启用新结果，再依第10节处理旧版本、备份和历史退出，不能由名称替换立即推出可以清理。

并行新旧视图有助于渐进演化，但意味着额外存储、处理、核查和运维成本。新规则结果不同可能是预期变化，也可能是缺陷；两者要按原目标分开判断。旧版本可回退还需要支持当前输入、保留必要资料且满足请求要求，不能只因为旧目录仍在就声称可回退。

纯状态重建不得自动重做历史通知或其他外部动作。新派生版本身份也不是给原业务意图换一个新操作身份的理由。需要继续外部动作时，保持与原意图绑定的身份、输入、历史结果和实际权限，并核对旧调用是否仍可能生效；具体复用[外部结果未知方法](message-atomic-effect-recovery.md#6-外部能力决定未知后的动作)。内部检查点无法撤销已离开处理器的动作。来源D21、D22、D39、D40；适配A04。

## 8. 用独立预期对账并定位差异

### 8.1 先让两边说的是同一件事

选择能够复查的权威输入范围与处理含义，使预期和被检查结果对应同一切点、依赖、格式、规则及配置。正在变化的源当前值与较早派生结果不同，可能是滞后；这不等同于永久错误。需要固定比较范围或取得相应历史结果，不能混着比较后统一“修正”。来源D42、D44、D45；适配A05。

独立预期来自给定业务事实、规则及可靠材料，可以是小范围手工推导、另一种独立实现或可验证的不变量。另一种实现也要核对是否共享了同一错误逻辑、错误过滤条件或损坏输入。把候选方法再运行一次，不自动形成独立判据。

对按r1（允许两组）构造的结果，本例S4及完整变化5、6、7给出青组[C@1]、橙组[A@1]。实际结果却为青组[D@1]、橙组[A@1]。总数同为2，逐项差异仍是缺少C且多出D。只抽到A看不出问题；两个错误实现都输出A、D也不能证明正确。

| 核对方式 | 能支持的结论 | 需要保留的限制 |
| --- | --- | --- |
| 逐身份与关键字段比较 | 被完整比较范围中的缺项、多项及值差异 | 同一切点、完整对象集和规则含义仍要有依据 |
| 业务不变量 | 给定约束是否满足，例如成员与数量一致 | 满足少数约束不证明全部结果正确 |
| 总量或分组数量 | 某些漏项、重复及聚合异常 | 缺一多一可能抵消，不能代替身份比较 |
| 规范化摘要 | 所声明材料、范围和编码的比较，或副本字节核验 | 不证明最初业务事实正确，也不自动覆盖未纳入资料 |
| 有限样本 | 已检查项目的结果，或对明确抽样设计的有限推断 | 没有完整覆盖依据时不声称全部已通过 |

正文位置、请求范围和输出资料都绑定清楚后，才组合这些证据。文件能打开、签名有效或摘要相同，各自都不是完整业务对账。来源D44、D45、D46；适配A05。

### 8.2 根据差异决定补齐还是重建

| 差异线索 | 下一步核对 | 有依据的处置方向 |
| --- | --- | --- |
| 缺项或连续位置空缺 | 捕获范围、保留材料、确认与效果是否错配 | 补取得必要输入并按原身份应用；范围未知时重建有依据基线 |
| 重复效果或数量异常 | 固定输入、去重记录、共同保存及旧贡献 | 核查已发生效果，修复恢复条件，再重算或受控修复对应范围 |
| 老值覆盖新值 | 顺序、对象生命周期、版本及迟到写者 | 保留正确新事实，修复实际写入保护，再恢复相应派生结果 |
| 删除对象仍在 | 删除捕获、关联贡献、缓存、旧快照及当前控制 | 保证受影响访问符合当前删除要求，补齐派生删除和恢复控制 |
| 同一输入重算不同 | 代码、规则、配置、时间和历史关联 | 固定必要依赖，区分原恢复与新含义版本 |
| 不同版本结果混在一起 | 输出位置、活动版本、查询路径和后台写者 | 隔离受影响结果，完成版本绑定及读写资格核查 |

局部修复要绑定来源范围和目标版本，并防止并发新变化被旧修复覆盖。仅把计数改成看起来正确，会掩盖贡献或输入缺口；直接猜测权威事实更不成立。源资料本身有错时，应取得业务依据并按有授权的事实纠正路径处理，不能让对账工具自行编造历史。

缺口范围已知、必要输入完整且局部修复可受实际版本保护时，可比较补齐；输入、依赖或影响范围无法确定，或者局部修复无法解释全部贡献时，比较从可靠基线构造新结果。记录差异原因、所用输入、已经核实的修复范围和仍待核项目，不把“已安排重建”写成“已恢复”。来源D25、D42、D45；适配A05。

## 9. 在实际读写位置启用新结果

新结果通过指定范围的核查后，还要满足当前请求所需的全部输入、查询含义和当前访问控制。记录活动版本、输入最低要求、查询可见范围及实际读写资格；切换步骤不能凭进程自报状态完成。来源D24、D28、D30、D37、D42；适配A03、A04。

W1在读取G1和旧资格后暂停，控制随后启用G2。W1恢复时，可能返回旧响应，也可能向先前解析的共享目标写入。只改别名或路由不会结束它。构造过程中没有影响G2的独立位置，也不自动保护活动查询或共享目标。

| 保护对象 | 实际条件 | 仍需检查的失败窗口 |
| --- | --- | --- |
| 派生写入 | 当前版本与资格在目标修改发生时受原子条件写、互斥或已证明等价能力保护 | 仅读旧控制快照、先检查后无条件写入、重启后丢失限制 |
| 隔离结果位置 | 旧处理者不能写入新输出，路由和权限与版本相符 | 共享别名、误配目标或后台工具绕过隔离 |
| 查询与已在途响应 | 返回结果满足该请求的版本、完整输入及控制要求 | 请求切换前进入，返回时仍冒充G2；缓存和长连接提供旧结果 |
| 回退与旧版本退出 | 回退目标支持当前输入及观察，旧写者和恢复路径受到约束 | 旧版本仍可重启，旧备份恢复后重新取得效果资格 |

同一资源能共同保护控制和写入时，采用实际有相应冲突或互斥保护的提交；普通事务里仅读旧控制值不一定够。控制和目标分离时，须验证目标资源实际使用资格并保留其限制、覆盖全部写路径及故障恢复。一个较大的代数、租约到期或通知到达，都不能独自证明旧工作已停止。必要时比较实际资源权限隔离或受控结束在途工作，但仍保留不能证明的范围。

请求明确允许历史G1结果时，可以按原含义返回并标明范围；请求要求G2和完整位置7时，旧G1响应不满足它。查询入口、缓存、客户端及结果交接按实际参与范围决定怎样拒绝、等待或重新取得符合要求的结果。最低观察要求不是整个系统的所有用户都必须最新，而是当前任务已经承诺的具体结果。

切换失败时核对哪一步已发生：新结果是否完整、当前活动版本是什么、哪些写入已完成、哪些请求仍在途、旧资格怎样受限。保持已经确认的新事实，按仍可成立的组合继续或恢复。停止切换、恢复旧查询和完成新版本分别记录，不能相互代替。跨版本资料与恢复资格复用[混合读写与恢复方法](mixed-version-data-migration.md)。

## 10. 联合判断恢复材料、容量与保留

### 10.1 复制、备份和重建能力分别检查

复制可能把错误或删除传播到其他副本。备份保存某个范围的旧资料，但未必含后续变化、规则或当前控制。重建要求足以产生所声明结果的完整输入和依赖。为每个恢复目标记录材料、切点、格式、处理版本、必要关联、后续日志、外部结果和控制的来源，以及它们能恢复的范围。来源D06、D16、D25、D44、D45；适配A02。

若备份状态只到7而进度是10，就不能直接从11恢复。若所需位置8已不存在、日志从9开始，也不能跳过8后仍宣称完整。先获取其他可靠材料或新的已核实基线；不能把重放请求成功当成源历史完整。

恢复默认在隔离目标内核查材料和结果。旧备份中可能存在已经删除的A@1，也可能保存旧活动版本与访问控制。在开放受影响访问和新增效果前，取得可证明为当前的删除、撤回及执行资格；“在另一个目录”不证明它独立于故障或回滚。缺少依据时可继续隔离核查，但相关访问和效果保持待核。来源D16、D24、D44；适配A02、A04。复用[恢复旧数据前取得当前控制](resource-retention-cleanup-recovery.md#10-恢复旧数据前取得当前控制)。

### 10.2 恢复期限取决于净处理能力与完整材料

虚构离散步模型初始积压10项，每步新增2项，每步最多应用3项。每步最多净减少1项；即使持续达到上限，也至少10步。未持续达到上限不能承诺10步赶上。如果每步最多应用1项，积压每步至少增加1项，不能赶上。数字只说明给定假设下的推理，不是任何真实系统的测量。来源D06、D25；适配A05。

实际恢复还要考虑基线读取和写入、事件应用、关联查询、数据核查、查询可见延迟及正常业务竞争。容量是实际完成的能力，不是工具标称上限；需要能解释启动、失败、并发和输入增长的证据。若条件不足，明确缺少哪项资料或容量，并比较保存完整输入、增加已验证处理能力、改变构造安排或取得可靠新基线。

保留是否足够不能仅比较两个时间数值。另一个独立题设中，一致初始材料到第10步才可就绪，期间不保存或应用必要后续输入，而最早必要日志在第5步结束后消失；此时追赶已缺材料。若另一方案在第5步前稳定保存了全部必要输入，其条件不同，不能从同样“保留5步”推出相同失败。

### 10.3 清理覆盖全部恢复和重放路径

列出活动结果、所有有关消费者、正在重建的新版本、离线使用者、允许的历史重放、旧备份和可能回退的版本。对每条路径说明所需来源历史、分区、最早必要材料、删除依据及处理依赖；只在相同范围内比较位置，不能直接取全部数字最小值或仅看最快消费者。来源D06、D07、D11、D20、D25；适配A02。

清理前确认需要保留的材料已有完整替代依据，或者相关恢复能力确实在授权范围内退出；清理与仍在继续的处理之间要有实际竞争保护。清理任务看到消费者已推进后，旧备份恢复或新重建仍可能提出较早需求。源日志清理、派生输出清理、删除标记清理和真实空间释放也不是同一个动作。

不能确认全部路径时，保留具体未知、必要输入和负责人；资源逼近约定上限时按原权限限制新增负载或调整方案，不为释放空间静默改变恢复承诺。证据、空间和恢复能力的共同判断复用[持续资源与保留方法](resource-retention-cleanup-recovery.md)。

## 11. 交付可采用的步骤与停止条件

输出深度按当前任务决定，可以是少量明确结论，也可以是带阶段证据的方案。关键是让下一位执行者知道哪些条件已成立、哪些仍需取得，而不是填写所有方法中的表格。

| 交付内容 | 应包含的具体依据 |
| --- | --- |
| 表示选择与更新路径 | 查询要求、简单方案是否足够、权威入口、候选适用条件和代价 |
| 输入与结果含义 | 来源历史、范围、变化类型、对象生命周期、格式及规则依赖 |
| 基线与连续恢复 | 一致快照和切点依据、后继输入、重复处理、效果与进度保存、缺口处置 |
| 对账与新版本 | 同一输入范围的独立预期、逐项差异、修复或重建理由、隔离版本绑定 |
| 服务与恢复资格 | 请求最低观察、查询可见、当前控制、旧写者与在途请求、可行回退组合 |
| 材料与期限 | 全部依赖与保留路径、实际处理能力、资源约束、责任者和下一步 |

只在范围覆盖、必要变化连续应用、语义核对、查询可见与当前控制均支持原要求时，报告相应派生结果可以按条件使用。对账完成到哪个切点、系统继续更新到哪里、是否满足当前请求，分别给出证据。

出现未解释的输入缺失或身份冲突、快照切点不明、必要依赖不可取得、删除对象重新出现、未知外部效果、无法约束旧写者、无法取得当前控制或超出原资源条件时，停止依赖该保证的推进，保留已经确认的事实和具体待核范围。任务允许的其他工作可以继续，不把不确定性统一改成失败或成功。

本方法在涉及派生更新、索引重建、数据对账、历史重算或相关恢复时按需使用。仅讨论单对象读取或普通代码变化时，先采用相应较小方法。复杂事务、重复顺序、数据格式、读取观察和保留问题分别通过上文的条件链接继续，不要求每个任务都加载全部资料。运行指导不依赖原书、私有提取环境或辅助审查服务。
