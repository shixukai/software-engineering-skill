## 1. 判断问题

怎样恢复服务而不让并行操作相互干扰？

## 2. 条件与证据

适用：

- 影响用户、跨团队或需要多人协同的故障响应指导

不适用或需调整：

- 孤立局部缺陷无需事故组织；仍按诊断流程处理

必要证据：

- 用户影响、时间线和当前服务状态
- 响应角色、操作权限及沟通渠道
- 已执行动作、待验证假设和恢复标准

## 3. 操作与取舍

1. 按既有标准确定事件等级和协调人，先明确用户影响与恢复目标。
2. 区分技术操作、协调、沟通与跟进责任，小事件可由同一人承担多角色。
3. 维护简短实时状态、动作、结果与未决风险；避免多人独立修改同一系统。
4. 交接时明确接任确认和当前风险；恢复动作保持在用户授权及既有操作权限内。

- 明确分工降低协调错误，也有沟通负担，应按规模调整。
- 恢复与根因调查可并行，但未经验证的根因不能阻止必要止损。

## 4. 验证与反例

- 每项状态变更有责任人、时间与结果
- 当前协调和操作责任清楚
- 恢复标准满足后仍保留后续调查与遗留风险

反例：三人分别重启、切流与回滚，彼此不知情，最终无法判断哪一步改变了现象。
