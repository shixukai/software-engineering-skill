## 1. 判断问题

能否把新增能力做成独立可测的小块？

## 2. 条件与证据

适用：

- 需要加功能而原类的依赖难以立即解除
- 新行为可用连续独立步骤表达

不适用或需调整：

- 新行为与原状态和时序强耦合，无法清楚传入传出
- 以新代码单测通过宣称整条旧路径已验证

必要证据：

- 准确修改点
- 新行为所需输入、返回值和副作用
- 旧调用点可获得的验证手段

## 3. 操作与取舍

1. 比较在原处直接加逻辑与新增方法或独立类
2. 显式传入原方法所需变量，确定返回值
3. 独立实现并测试新行为
4. 把调用接入旧路径，检查参数、顺序、结果使用和副作用，保留未覆盖接入风险

- 能让新增部分可测，但旧方法仍可能缺少保护
- 暂时拆出的代码可能缺少理想上下文，后续改善应有实际任务依据

## 4. 验证与反例

- 新行为测试通过
- 至少有针对接入点的检查或可解释验证
- 报告清楚哪些旧行为仍未覆盖

反例：新过滤函数单测通过，但原调用处仍把未过滤列表写出，新增能力实际上没有生效。
