## 1. 判断问题

测试结束时是否真的观察到了本次异步操作？

## 2. 条件与证据

适用：

- 消息、后台任务、事件或线程的结果在触发后才可见
- 测试偶发失败或在异步工作未执行时通过

不适用或需调整：

- 纯同步逻辑不要人为引入轮询
- 不能把延长超时或无限重试视为解决间歇失败

必要证据：

- 该次操作的可识别完成信号
- 时间上限与环境负载条件
- 线程或任务中的异常传播方式

## 3. 操作与取舍

1. 选择能与本次输入关联的状态变化或事件，确保空转、旧结果和未执行不能满足成功条件。
2. 触发后通过监听或有界轮询等待成功，成功即结束；超时报告最后观测状态、等待条件及后台错误。
3. 集中管理可说明理由的超时与轮询频率，兼顾响应、环境差异和观测负载。
4. 间歇失败先区分真实并发缺陷、同步错误和环境问题；暂时隔离时记录负责人和修复条件，并明确缺失的发布证据。

- 监听反馈快但需要可靠事件和先后顺序处理；轮询适用广但可能错过短暂状态或增加负载
- 超时过短制造噪声，过长拖慢故障反馈

## 4. 验证与反例

- 未完成、失败和成功三种路径可区分
- 观察对象能关联本次触发，后台异常不会静默丢失
- 没有无界等待，诊断能定位超时上下文

反例：提交异步任务后立刻检查初始值仍为零；后台线程根本没执行，测试却通过。
