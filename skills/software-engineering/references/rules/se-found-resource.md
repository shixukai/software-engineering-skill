## 1. 判断问题

资源由谁释放，部分失败后还剩什么？

## 2. 条件与证据

适用：

- 使用文件、连接、内存、锁、线程、订阅等有限资源
- 所有权转移或异常路径改变

不适用或需调整：

- 纯值计算没有资源获取和生命周期变化

必要证据：

- 获取、转移、使用和释放点
- 正常/失败/取消路径与资源限额

## 3. 操作与取舍

1. 为每项资源指定唯一清理责任或明确的共享所有权协议；返回、借用与转移所有权在接口中可辨。
2. 把获取和释放放在可审查的作用域或受控拥有者中，使用当前语言支持的确定性清理机制；不要把垃圾回收等同于及时关闭外部资源。
3. 逐项推演获取中途失败、早退、异常与取消；只释放确实取得且仍由本方拥有的资源，避免泄漏、重复释放和释放后使用。
4. 嵌套资源按依赖关系释放；列出常态和峰值需求，必要时设上限和拒绝/等待政策。
5. 检查重复完成或失败之后资源计数能回到约定基线；拥有者跨越调用时检查最终清理与退出顺序。

- 包装与所有权协议有设计成本，但分散清理更难审查
- 缓存或池有意保留资源时基线不是零，应验证上限和关闭

## 4. 验证与反例

- 成功、失败与取消的清理责任完整
- 长期积累与部分初始化失败有对应检查

反例：把打开留给读函数、关闭留给可选写函数，会在跳过写入时泄漏；全局垃圾回收不能证明文件及时关闭。
