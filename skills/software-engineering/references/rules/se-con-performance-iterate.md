## 1. 判断问题

这次收益是否抵偿复杂度和其他资源代价？

## 2. 条件与证据

适用：

- 已有性能瓶颈，准备比较具体优化

不适用或需调整：

- 不能验证结果一致性
- 指标已达目标且没有进一步优化价值

必要证据：

- 同条件的旧新测量
- 正确性和资源基线
- 可维护性及回退成本

## 3. 操作与取舍

1. 一次改变一个可解释因素
2. 先核对行为与误差契约，再比较相同负载下的收益和波动
3. 记录失败或无收益尝试并回退，不因代码显得聪明而保留
4. 优化后重新测整体，达到目标或边际收益不足时停止

- 多次小优化可叠加，也可能互相抵消
- 性能提升可能牺牲可读性、内存或调试便利，须记录理由

## 4. 验证与反例

- 正确性检查通过
- 端到端或目标指标改善，而非仅局部假象
- 收益、成本、适用环境和回退点可复核

反例：指针改写未带来可重复收益却留下难读实现；编译器可能早已完成同样的优化。
