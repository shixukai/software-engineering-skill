## 1. 判断问题

错误分类能否帮助调用者作出不同决定？

## 2. 条件与证据

适用：

- 第三方错误类型泄漏到多个业务调用者
- 异常缺少操作背景或被重复转换

不适用或需调整：

- 不同失败需要不同补救却被压成一种无信息错误
- 现有跨边界协议已经规定错误表示

必要证据：

- 各错误的处理和传播路径
- 调用者需区分的失败类型
- 可安全记录的上下文

## 3. 操作与取舍

1. 按调用者要采取的动作分组错误
2. 在边界集中转换供应商细节，保留原始原因
3. 提供失败操作和必要标识；按数据敏感性限制日志内容
4. 对必须不同处理的错误保留可区分类型或结构化状态

- 稳定错误接口降低供应商耦合
- 过度合并损失诊断和恢复信息；过细分类又让调用者依赖实现

## 4. 验证与反例

- 不同恢复动作仍可被正确选择
- 原因链和操作背景足够定位
- 日志不泄露凭据或不必要数据

反例：权限不足与暂时不可达都转成一个无原因的失败，调用者便无法决定应纠正权限还是等待重试。
