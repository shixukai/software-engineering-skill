## 1. 判断问题

复用实现是否需要暴露父类内部结构？

## 2. 条件与证据

适用：

- 考虑通过子类复用实现
- 需要替换行为且继承使变化传播

不适用或需调整：

- 稳定框架明确要求扩展点继承，且满足父类契约
- 简单组合导致更多难以追踪的动态对象

必要证据：

- 父子类型契约与覆写点
- 复用的是接口还是具体实现
- 是否需要运行时替换及对象生命周期

## 3. 操作与取舍

1. 分别说明继承与持有协作者的实现方式
2. 检查子类是否依赖父类内部细节以及变更后的连锁影响
3. 需要独立替换实现时优先比较通过窄接口组合
4. 保留必要继承，避免为组合而增加无价值的委托链

- 组合减少实现耦合，但增加对象和转发代码
- 继承可直接使用默认实现；动态委托更灵活也更难追踪

## 4. 验证与反例

- 替换协作者或覆写方法后外部契约成立
- 对象所有权和生命周期明确
- 阅读一次操作能追到真实执行者

反例：只因窗口用到面积计算就继承矩形，会把几何实现误当类型关系；反过来，成熟框架规定的扩展子类也不应机械改成层层包装。
