## 1. 判断问题

各个操作线程安全，组合后的业务步骤也安全吗？

## 2. 条件与证据

适用：

- 多线程、并发任务、共享可变状态或跨线程发布对象
- 将串行步骤并发化

不适用或需调整：

- 没有共享状态与时序依赖的纯顺序变更

必要证据：

- 共享读写及业务不变量
- 实际语言/运行时版本的同步和内存模型文档

## 3. 操作与取舍

1. 列出共享状态、所有读写者及需要一起成立的条件；优先评估独占所有权、不可变快照或消息传递以减少共享。
2. 将检查、修改和发布的交错写出来，确定业务原子边界；单个容器方法安全并不保证多次调用组合安全。
3. 核实对象初始化、发布及结果观察之间的同步关系。锁、原子操作或消息机制必须依据目标语言和库的文档；墙钟先后、sleep 和测试偶尔成功不构成可见性保证。
4. 选择保护完整不变量的同步范围，避免为了缩短锁而把关键检查移出；同时控制不必要的临界区工作。
5. 把局部逻辑与调度分开验证，针对危险交错设计受控检查，必要时运行相应竞态检测；测试通过不证明所有调度正确。

- 复制减少共享但增加内存与合并成本
- 扩大临界区简化正确性但增加争用；原子单变量不能自动保护多个字段

## 4. 验证与反例

- 每条共享访问遵循同一协议
- 原子性、可见性和业务不变量分别有依据

反例：先调用线程安全 contains，再调用线程安全 insert，仍可能被另一个执行者插入；把标志设为完成也不自动发布关联对象。
