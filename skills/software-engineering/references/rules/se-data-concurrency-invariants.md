## 1. 判断问题

当前隔离或锁能防住实际竞争吗？

## 2. 条件与证据

适用：

- 先读后写、唯一性检查或跨对象约束在并发下执行

不适用或需调整：

- 真正不可并发的离线一次性处理；仍核实该前提

必要证据：

- 读集合、写集合与业务不变量
- 事务边界、隔离级别和锁范围
- 中止重试行为与外部副作用

## 3. 操作与取舍

1. 写出两个操作可能的交错，分别检查丢失更新、写偏斜与空结果上的并发插入。
2. 优先选能表达约束的数据库约束或原子操作；复杂约束比较显式锁、版本检查与可串行化事务。
3. 验证所有写入路径都使用同一规则，检查空查询是否真的锁住所需范围。
4. 处理中止与冲突时重新读取并重算；重试整段工作前隔离不可回滚副作用。

- 悲观锁增加等待与死锁风险，乐观控制增加中止和重试负载。
- 更强隔离常比手工维护复杂锁协议简单，但代价须按负载验证。

## 4. 验证与反例

- 交错执行的检查使用独立会话而非顺序调用
- 结果保持不变量，或明确返回可处理冲突
- 同名隔离级别的能力以当前产品文档和实验核实

反例：每次插入前先查询不存在重复记录，在快照下两个请求都看到空结果，随后都插入成功。
