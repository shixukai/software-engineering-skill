## 1. 判断问题

没有数据错误时，任务是否仍可能永远等下去？

## 2. 条件与证据

适用：

- 锁或多资源获取
- 生产者消费者、后台任务、优雅关闭与取消

不适用或需调整：

- 没有阻塞、等待或后台活动的纯局部计算

必要证据：

- 等待者、持有资源和唤醒/结束条件
- 取消、超时与关闭协议

## 3. 操作与取舍

1. 画出谁持有什么、等谁释放或发送什么；检查环形等待与锁定区域中的外部阻塞。多资源获取采用一致次序或其他有依据的死锁避免协议。
2. 为队列、并发数和等待设与业务相符的边界；生产速度超过消费能力时选择背压、拒绝或降级，不能无限积压。
3. 定义停止接收、通知生产/消费停止、处理或移交在途任务、等待结束和释放资源的次序；确保任何等待者都能观察到结束或失败。
4. 区分超时结束等待与操作实际停止；验证取消传播、任务异常、重复关闭以及部分组件先退出的情形。

- 有界等待可能使原本可完成的慢任务失败，需要业务预算
- 一致获取顺序可能降低并行度，取消也不能抹除已发生副作用

## 4. 验证与反例

- 等待路径有可达到的完成/失败出口
- 关闭后的在途工作和资源状态符合约定

反例：生产者已退出而消费者仍等待下一条消息，主线程再等待消费者，关闭过程永远无法完成。
