## 1. 判断问题

哪些现有行为需要在这次修改中保护？

## 2. 条件与证据

适用：

- 遗留代码缺少可信行为基线
- 需要先理解将要改动的区域

不适用或需调整：

- 把观察到的现状直接当成正确需求
- 只靠快照覆盖大量未知行为而不评估变更相关性

必要证据：

- 拟修改区域及其输出和副作用
- 可重复的当前行为
- 已知需求和可疑差异

## 3. 操作与取舍

1. 将目标代码放入测试用具，用最简单输入观察当前行为
2. 必要时用预期失败的断言取得实际结果，再记录现状
3. 扩展到本次修改相关的边界、路径和状态，不追求无限枚举
4. 可疑结果标为待确认，行为修复单独获得需求依据并更新相应期待

- 特征测试减少改动不确定性，却可能保存已有缺陷
- 测试范围应由即将发生的改动和理解需求驱动

## 4. 验证与反例

- 测试可重复并能识别意外行为变化
- 可疑行为与已认可契约分开登记
- 未覆盖的外部副作用明确

反例：当前实现把非法日期默认为某一天，特征测试可记录这个事实，但不能因此宣称该默认就是产品正确规则。
