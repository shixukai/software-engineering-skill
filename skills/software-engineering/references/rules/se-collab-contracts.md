## 1. 判断问题

谁必须知道这次变化，哪些内容足以使其正确协作？

## 2. 条件与证据

适用：

- 团队共同依赖接口、数据或交付时点
- 重复讨论、信息不同步或会议占用妨碍交付

不适用或需调整：

- 不要求所有成员阅读全部内部实现
- 不把减少会议等同于减少必要协作
- 不自行向外部人员发消息或改变团队职责

必要证据：

- 接口与依赖的生产者、消费者
- 当前决定、约束、未决事项及责任人
- 会议或文档需要支持的具体决定

## 3. 操作与取舍

1. 保留一份可找到的当前接口和关键决定，记录适用版本、变更影响及负责角色；内部实现按边界封装。
2. 变更会影响消费者时明确哪些约定改变、何时生效、怎样验证和如何协调迁移。
3. 对需要共同决策的问题限定议题、必须参与者和结束条件；单纯状态可用可追踪记录分发，避免防御性全员到场。
4. 文档只保留能帮助执行、解释决定或预警的信息；校验接收方理解与依赖动作，别以开过会代替达成共识。

- 信息隐藏减少认知负担，但接口语义必须足够完整
- 书面记录降低重复沟通，仍需解决歧义的对话；正式记录的深度应匹配风险

## 4. 验证与反例

- 受影响消费者和迁移责任可定位
- 决策记录与当前接口一致，未决项不写成共识
- 会议输出包含决定或明确下一步；无必要不会无限续会

反例：接口超时语义改变但只在实现组口头讨论，消费者继续按旧约定重试；项目周会上全员出席也不能弥补契约缺失。
