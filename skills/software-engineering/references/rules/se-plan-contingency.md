## 1. 判断问题

如果最重要的假设失败，何时启动什么替代方案？

## 2. 条件与证据

适用：

- 交付日期有高昂下游后果
- 技术、供应方或本团队履约存在显著不确定性

不适用或需调整：

- 不把风险清单变成所有可想象问题的目录
- 概率或影响未知时先登记不确定性，不伪造数字打分

必要证据：

- 失败情境与受影响目标
- 最迟决策时间和预案准备周期
- 可用替代方案、责任人及必要资源

## 3. 操作与取舍

1. 同时检查外部依赖失败和自身估计、技能、集成或验收不能达成的可能，不因“必须成功”删除风险。
2. 把风险写成条件、后果和可观察触发信号，优先处理影响大或准备窗口长的项。
3. 为相关风险选择避免、降低、接受或预备替代路径；写明负责人、准备动作和启动时点。
4. 定期依据新证据更新风险，重大前提失效时及时重估范围和日期；对状态信息和需决策事项分别说明。

- 预案占用当前资源，按损失与准备窗口决定投入
- 有价值的探索允许承担风险，但承担应是知情选择

## 4. 验证与反例

- 高影响风险有触发条件和可执行响应
- 本团队履约风险没有被道德评价或乐观承诺掩盖
- 需要提前准备的资源已有负责人或显式缺口

反例：计划写“发布日期不可延误”，因此不安排替代服务；等到依赖延迟确认时，预案也来不及准备。
