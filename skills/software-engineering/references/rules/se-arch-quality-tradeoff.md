## 1. 判断问题

哪种方案在当前约束下值得实现？

## 2. 条件与证据

适用：

- 新系统或影响质量属性的架构决策
- 候选方案对性能、可靠性、成本或演进有不同影响

不适用或需调整：

- 纯局部改动且没有可说明的架构影响；保留局部分析

必要证据：

- 目标用户与关键业务操作
- 质量目标、业务影响、负载参数及不确定性
- 资源、交付时间、团队能力和既有约束

## 3. 操作与取舍

1. 把“快、可靠、可扩展”改写为操作、负载、观察窗口、目标和失败影响；没有依据的数值标为待验证。
2. 比较满足需求的最简单候选与必要备选，说明数据与组件边界、依赖和故障传播。
3. 对最影响选择的假设安排可区分方案的实验，记录选择、舍弃理由、成本和重新评估触发条件。

- 更高可靠性和容量有设备、开发与维护成本；最大化所有指标会损害交付。
- 决策记录应与风险相称，轻微变化不需要完整报告。

## 4. 验证与反例

- 每个关键选型能对应需求或约束证据
- 关键假设有验证方式，方案代价与剩余风险明确
- 区分需求目标、估算和实测结果

反例：仅因未来可能增长就引入多集群、消息总线和分布式数据库，没有对应负载或隔离需求，增加了当前不能承担的维护成本。
