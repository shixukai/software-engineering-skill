## 1. 判断问题

缓存、索引和分析副本怎样恢复一致？

## 2. 条件与证据

适用：

- 一份业务数据写入多个系统
- 需要重建索引、缓存或数据投影

不适用或需调整：

- 独立数据之间不要求同步，或单一存储已满足需求

必要证据：

- 权威记录系统、变更顺序和派生用途
- 新鲜度要求、丢失容忍及重建时限
- 变更保留期、快照位置和消费者进度

## 3. 操作与取舍

1. 区分权威数据与可重建投影，描述可接受延迟及业务读取路径。
2. 识别双写的部分失败与乱序窗口，比较单一事务边界、变更日志或变更数据捕获。
3. 为日志消费设计幂等、版本顺序、进度恢复和删除传播。
4. 重建时把一致快照与日志位置衔接，监测滞后并验证投影与源数据的一致性。

- CDC减少双写窗口，却增加日志保留、模式演进与消费者运维。
- 可重建不代表恢复足够快；要把恢复容量计入设计。

## 4. 验证与反例

- 模拟中断后能从确定位置继续且不漏更新
- 快照与日志交界没有缺口或错误重复
- 删除、重放和模式变化后的投影符合权威数据

反例：两次写入都成功，但并发写在数据库和索引中先后顺序不同，数据永久分歧。
