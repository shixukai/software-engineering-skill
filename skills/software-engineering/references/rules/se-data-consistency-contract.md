## 1. 判断问题

哪些读取必须看到哪些写入？

## 2. 条件与证据

适用：

- 有复制、缓存、多节点访问或对一致性作出承诺

不适用或需调整：

- 单一顺序处理且不存在并发或副本读取；无需全面讨论分布一致性

必要证据：

- 读写路径及副本拓扑
- 用户对陈旧、回退、顺序、数据丢失的容忍度
- 当前存储版本与实际配置

## 3. 操作与取舍

1. 区分持久性、读己之写、单调读、因果顺序、单对象新鲜度与多对象事务隔离。
2. 为不同操作选最小足够保证；写后读可评估读主或按已知版本等待合格副本。
3. 说明同步复制等待与异步复制数据丢失窗口；分区时明确拒绝、等待、降级或冲突处理。
4. 核实产品版本和配置的真实保证，不能仅凭 ACID、强一致或 CAP 标签判断。

- 更强保证可能增加延迟、协调成本或分区期间不可用。
- 较弱保证要在体验和业务约束中消化陈旧值与冲突。

## 4. 验证与反例

- 为必须保障的观察顺序构造并发及故障检查
- 拒绝或降级语义与业务约定一致
- 不以正常网络下的样例证明分区行为

反例：采用线性一致的单条读写就声称跨多条记录的不变量安全，混淆了新鲜度与事务隔离。
