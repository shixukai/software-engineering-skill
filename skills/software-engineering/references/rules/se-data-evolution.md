## 1. 判断问题

新旧读写者能安全共存和回退吗？

## 2. 条件与证据

适用：

- 更改持久数据、API或消息格式
- 滚动发布、延迟消费或版本回退

不适用或需调整：

- 完全私有临时格式且可证明没有旧读写者或留存数据

必要证据：

- 实际生产者与消费者版本组合
- 历史数据和消息保留期
- 字段语义、默认值、未知字段行为及回退范围

## 3. 操作与取舍

1. 列出旧写新读、新写旧读、新旧读改写及历史消息重放组合。
2. 区分语法可解码与业务含义兼容，检查缺字段、默认值、枚举和语义变化。
3. 显式检查旧代码回写时是否丢弃未知字段，安排分阶段发布与数据迁移。
4. 只有确认旧读写者和保留数据退出后才移除兼容支持；无法无损回退时给出前滚恢复。

- 兼容期增加双版本维护成本；过早删除会让回滚与迟到消息失败。
- 长期保留所有版本也会累积复杂度，需要可核查退出条件。

## 4. 验证与反例

- 混合版本契约测试和历史数据读取通过
- 未知字段往返后仍按预期保留
- 回退或前滚恢复路径有明确结果

反例：新字段能被旧解析器忽略，却在旧服务读改写时被静默删除，误把可读取当成无损兼容。
