## 1. 判断问题

系统持续运行后会因积累而失效吗？

## 2. 条件与证据

适用：

- 日志、缓存、队列或持久数据持续增长

不适用或需调整：

- 确实有限且不可变的数据集合，不强加周期清理

必要证据：

- 资源增长与回收速率、上限
- 数据保留、审计、重建和依赖要求
- 达到上限时的行为与清理成本

## 3. 操作与取舍

1. 列出会累积的资源以及正常和异常增长路径。
2. 为缓存、日志和积压设置符合业务的限额与生命周期，清理保持引用和逻辑完整性。
3. 将容量告警与预测耗尽时间相连；清理失败或存储写失败必须受控。
4. 验证回收过程不会造成长时间锁、阻塞或误删，必要时分批执行并保留恢复办法。

- 回收降低无限增长风险，但消耗I/O、可能影响数据追溯。
- 书中技术和合规示例只作历史背景，保留期限以当前有效要求核实。

## 4. 验证与反例

- 持续运行中资源增长稳定在允许范围
- 回收失败能被发现，达到上限不会连锁崩溃
- 应保留数据与删除传播符合当前要求

反例：定时重启暂时释放缓存，却没有限制键空间；故障周期随流量增加越来越短。
