## 1. 判断问题

无需修改待测试调用处，能在哪里替换依赖行为？

## 2. 条件与证据

适用：

- 外部依赖妨碍运行或观察目标代码
- 为遗留代码建立首个测试边界

不适用或需调整：

- 只有接口名而无可控制的实例、构建或链接选择点
- 替换依赖后把生产接线验证一并省略

必要证据：

- 阻碍测试的依赖及副作用
- 可用接缝与激活点
- 测试和产品构建或对象选择的差别

## 3. 操作与取舍

1. 明确需要感知调用还是分离副作用
2. 找现有对象、链接或预处理接缝，并写清控制行为的激活点
3. 优先选择清晰、局部且改动少的接缝；必要的初始改动保持保守
4. 用替身感知需要的结果，再单独核对产品仍连接到真实依赖

- 对象接缝通常显式；链接和预处理可能少改源码却让构建差异隐蔽
- 创建接缝本身也有风险，不能宣称已被尚未建立的测试保护

## 4. 验证与反例

- 测试能够通过激活点选择替身
- 生产路径保留应有行为
- 构建差异显式并且替身不会误入产品

反例：方法内部直接 new 一个固定实现后立即调用，即使类型有多态方法，也不自动形成测试可控制的对象接缝。
