## 1. 判断问题

这条意见指出了可触发的缺陷，还是偏好或待验证风险？

## 2. 条件与证据

适用：

- 代码或设计审查，需要决定哪些意见值得报告

不适用或需调整：

- 仅凭书中原则或命名偏好断言存在缺陷
- 没有当前差异和必要上下文却给具体故障结论

必要证据：

- 变更差异、调用者和适用契约
- 触发输入、执行路径与影响
- 测试、类型检查或可复核的推理

## 3. 操作与取舍

1. 先理解目的和约束，再按与改动有关的失败场景独立阅读
2. 对每个问题记录位置、触发条件、受影响行为和依据
3. 区分已证实缺陷、需验证风险与可选可读性建议，不给偏好虚构严重性
4. 交付有限的行动项并根据修复影响跟进验证；本次找不到问题可明确无发现

- 正式检查的准备、记录和复查有价值，但不必为每个小改动安排全套会议角色
- 清单辅助聚焦，不能替代上下文和证据

## 4. 验证与反例

- 他人可依据位置和条件复核问题
- 每条严重性对应实际影响
- 修复结果回到原发现验证且不过度扩大范围

反例：函数超过作者偏爱的行数不能证明它有缺陷；发现可能为空的变量也须核实调用契约和可达路径。
