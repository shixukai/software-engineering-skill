## 1. 判断问题

失败时继续、降级还是停止，哪一种符合契约？

## 2. 条件与证据

适用：

- 实现输入校验、异常或返回错误处理
- 同类失败被不同模块各自处理

不适用或需调整：

- 以统一默认值掩盖必须准确的结果
- 把某种语言的异常偏好当跨语言硬规则

必要证据：

- 调用者能采取的补救动作
- 错误结果的成本与可恢复性
- 状态和资源在中断后的约束

## 3. 操作与取舍

1. 区分有效空结果、可恢复失败与不可信状态
2. 选择局部处理、向上报告、降级或停止，并明确处理责任
3. 错误分支保持状态一致并释放已取得资源；处理异常本身不自动回滚业务效果
4. 核查所有报告路径最终有人处理，避免空捕获或伪装成功

- 继续服务和结果准确性可能冲突，须按具体功能判断
- 集中处理利于一致性，也可能引入全局耦合

## 4. 验证与反例

- 每类失败都有可观察结果和处理者
- 失败前后的资源及状态满足契约
- 测试覆盖失败中断，不把 try/catch 视为事务保证

反例：读取失败直接返回空集合，可能让调用方把未知状态理解为确实没有记录，并据此执行破坏性后续操作。
