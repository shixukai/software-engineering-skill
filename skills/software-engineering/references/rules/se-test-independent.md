## 1. 判断问题

失败来自产品还是测试之间的污染？

## 2. 条件与证据

适用：

- 测试使用可变状态、数据库、文件、共享资源或外部环境
- 测试单独运行、换顺序或并发时结果不一致

不适用或需调整：

- 有意验证多步骤事务的一个场景不必拆成彼此无意义的小测试
- 昂贵且只读的共享夹具可复用，但须验证隔离前提

必要证据：

- 测试依赖的初始状态、资源所有权与清理路径
- 失败时残留内容和执行顺序
- 随机、时钟、身份及外部输入的控制方式

## 3. 操作与取舍

1. 显式区分夹具建立、执行被测行为、结果验证和清理；优先使用本测试拥有的最小夹具。
2. 控制会改变结果的时钟、随机数及环境输入；对共享资源采用独立命名或可验证的隔离措施。
3. 确保异常路径也能清理自己创建的状态；不删除不属于测试的资源。
4. 用单独运行、重复运行及相关顺序变化定位污染；修复污染后保留能检测它的检查。

- 独立夹具增加建立成本，应优化创建方法而不是隐藏测试依赖
- 事务回滚或共享只读数据能降低成本，但其隔离语义须按当前实现验证

## 4. 验证与反例

- 测试无须前导测试即可建立合法状态
- 失败清理后再次执行结果一致
- 共享夹具假设有保护或独立验证

反例：测试B依赖测试A先创建一条记录；整套测试通过，单独执行B失败，反馈不能定位产品缺陷。
