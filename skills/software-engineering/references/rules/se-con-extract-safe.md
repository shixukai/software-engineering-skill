## 1. 判断问题

把这段代码移到新函数后，值、顺序和副作用是否保持？

## 2. 条件与证据

适用：

- 通过提取函数理解或隔离一段实现

不适用或需调整：

- 尚不清楚被赋值局部变量的后续用途
- 复杂控制流无法用当前步骤安全保持

必要证据：

- 读写变量、作用域与别名
- 返回值、异常、早退及副作用
- 现有测试和编译检查入口

## 3. 操作与取舍

1. 以意图命名新函数，先原样移动目标代码
2. 将新作用域缺失的输入作为参数，专属局部变量随代码移动
3. 检查每个被赋值变量的后续读取；一个输出可显式返回，多输出先考虑拆分变量等更小步骤
4. 编译后替换原调用并运行针对性行为测试；再处理其他重复调用

- 直接提取最快，但复杂可变状态会放大风险
- 先简化数据流可能多几步，却缩小每步的错误范围

## 4. 验证与反例

- 提取前后的关键输出、副作用和顺序一致
- 受影响转换、异常路径和调用点经过验证
- 失败后只需检查最后一步或回退该步

反例：把局部变量按值传给新函数并在内部赋值，却忘记将新值传回原函数，可能编译成功但改变后续行为。
