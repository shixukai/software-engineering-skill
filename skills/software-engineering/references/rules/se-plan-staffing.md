## 1. 判断问题

新增人手能加快关键路径，还是先拖慢现有团队？

## 2. 条件与证据

适用：

- 项目延期、赶工或考虑扩大团队
- 关键知识集中、交接或培训会占用已有产能

不适用或需调整：

- 不把“晚加人一定更晚”作为拒绝所有增员的普遍定律
- 不把人员当成完全可互换资源，也不自动决定招聘、调岗或绩效措施

必要证据：

- 可独立执行任务及关键依赖
- 新人技能匹配、上手时间与指导者负担
- 剩余窗口、重分工与集成成本

## 3. 操作与取舍

1. 判断瓶颈是人力不足、串行依赖、决策等待、技能缺口还是测试环境限制。
2. 对每种增员方案列出可接手工作、指导投入和何时开始产生净帮助；比较缩小范围、移除阻塞和调整顺序。
3. 在关键窗口较短时优先安排边界清晰且有上下文的人承担独立工作，不以人数简单平摊剩余工期。
4. 用实际产出、等待和协作负担复核方案，并保留团队持续工作的能力；人员管理动作交给有权负责人。

- 培训和接口工作先增加成本，但足够早且任务可分解的增员可能缩短工期
- 稳定团队能保留知识，专门技能的短期支持也可能有效

## 4. 验证与反例

- 增员针对的是已识别瓶颈
- 估算包含指导与重分工，不把新增人从第一天计作满产能
- 与不增员方案进行条件一致的比较

反例：构建环境尚未开通时再加五名编码人员，并不会缩短审批等待；反之，把独立数据核对工作交给熟悉领域的人可能有帮助。
