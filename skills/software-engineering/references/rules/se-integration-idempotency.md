## 1. 判断问题

重试会不会重复或倒退业务状态？

## 2. 条件与证据

适用：

- 消息可能重复、客户端可能重试或任务可能重放

不适用或需调整：

- 纯只读操作无副作用且不存在昂贵重复执行风险；仍可限制重复负载

必要证据：

- 业务操作身份、重试与重放期限
- 状态写入、去重记录和外部副作用的边界
- 顺序、版本及并发处理约定

## 3. 操作与取舍

1. 优先识别一次业务意图的稳定标识，不把相同消息内容直接等同于重复操作。
2. 让去重记录与受保护的本地副作用在同一可保证边界内提交；外部系统用其幂等或对账协议。
3. 选择去重保留范围并说明过期后重放行为。
4. 单独检查乱序和并发；赋值虽对连续重复幂等，也可能让旧消息覆盖新状态。

- 持久去重占存储并需要生命周期管理。
- 业务键复用为消息标识可能把合法后续更新误删，需区分业务对象与操作身份。

## 4. 验证与反例

- 重复、并发重复、乱序、确认丢失及重启后重放均符合契约
- 同一对象的两个合法操作不会被误判为重复
- 去重记录与副作用之间的崩溃窗口已检查

反例：把“设为版本3的状态”视为天然安全，版本4更新后版本3重投又把状态倒退。
