## 1. 判断问题

规模或输入分布变化后，当前算法还能满足预算吗？

## 2. 条件与证据

适用：

- 有循环、递归、批处理、搜索或排序
- 评估容量、响应或资源消耗

不适用或需调整：

- 输入规模固定且成本明显可忽略时不强制写形式推导

必要证据：

- 输入规模的定义与可能范围
- 基本操作成本、输入分布和平台约束

## 3. 操作与取舍

1. 明确规模变量：条数、字节数、图的顶点/边数或数值位数；分别估计时间和额外空间。
2. 沿循环界限、嵌套调用和递归展开计数，把比较、复制、分配及 I/O 的非恒定成本纳入。分别声明最坏、平均或摊还情形及其前提；不能仅凭一个嵌套循环标签断言复杂度。
3. O 是渐近上界，Ω 是下界，Θ 是同阶界；这些符号本身不分别代表最坏、最好、平均输入。用增长关系检查未来规模，保留常数、缓存和启动开销对当前规模的影响。
4. 若预算有风险，比较标准库算法、减少重复工作、调整数据结构与限制输入；在可比环境用不同规模及有代表性的输入形状验证估算，并确认结果正确。

- 更优渐近阶可能带来更高常数、额外内存或维护成本
- 平均情形依赖分布；少量测量点只能检验预测，不能证明复杂度

## 4. 验证与反例

- 规模变量、情形和基本操作成本明确
- 测量包含预期大规模与可能退化输入，结论不超出观察范围

反例：固定小集合上的简单扫描可能比建立并维护索引更便宜；不能只看 O 符号替换。
