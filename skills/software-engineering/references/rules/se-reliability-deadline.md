## 1. 判断问题

依赖变慢时何时停止等待和消耗资源？

## 2. 条件与证据

适用：

- 远程调用、资源池、队列或其他可能阻塞的等待位于请求路径

不适用或需调整：

- 有意长期运行的后台任务按独立进度、取消与恢复契约处理，不套用交互请求阈值

必要证据：

- 用户时限、调用链、排队与后处理开销
- 正常与长尾延迟分布
- 取消能力、不可逆副作用及恢复点

## 3. 操作与取舍

1. 从端到端时限分配剩余预算，覆盖连接、读写、池等待和排队；不逐层重新给予完整时限。
2. 使用适合测量持续时间的时钟，在阶段边界检查剩余预算并传播取消。
3. 超时只说明结果未知，查明操作是否可能已生效；重试前调用幂等与确认协议。
4. 恢复检查点或不可逆阶段不能盲目中断，明确安全停止与结果查询方式。

- 太短导致误判与重试，太长耗尽线程或连接。
- 取消信号未必停止远端效果，必须验证实际库和协议。

## 4. 验证与反例

- 黑洞、慢依赖和池耗尽时等待有界
- 总响应时限与资源释放可观察
- 超时后的已完成、未完成和未知结果有明确处理

反例：上游已经放弃，下游仍按自己的新超时继续排队和执行，大量无用工作耗尽资源。
