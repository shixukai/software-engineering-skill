## 1. 判断问题

重试有恢复收益还是只会放大故障？

## 2. 条件与证据

适用：

- 调用或消费失败后准备自动重试

不适用或需调整：

- 永久错误、格式错误、未经保护的非幂等副作用或已过有效时限

必要证据：

- 可重试错误分类、依赖健康与剩余容量
- 各层重试配置和端到端时限
- 副作用协议及当前请求/客户端重试量

## 3. 操作与取舍

1. 先判断错误是否可能短暂且再次执行安全；结果未知时不当作未执行。
2. 指定承担重试的一层，限制单请求尝试和总体重试流量。
3. 对持续故障采用有抖动的退避；广域过载时停止放大负载，按约定拒绝或降级。
4. 仅在确有其他健康实例、很低额外延迟和充足预算时考虑立即重试局部拒绝；记录条件。

- 重试可遮蔽短暂失败，也会消耗容量、拉长延迟并重复副作用。
- 书中具体次数、比例与时延是场景示例，不是通用配置。

## 4. 验证与反例

- 故障下注入请求量有上限
- 永久错误不重试，依赖恢复后能恢复正常流量
- 重试指标能区分初始请求、尝试和最终业务结果

反例：调用链每层都重试三次，最下游已经过载，却承受乘法放大的请求量。
