## 1. 判断问题

重跑或部分失败后，部署会留下什么状态？

## 2. 条件与证据

适用：

- 编写部署脚本、变更环境或更新组件组合
- 部署可能被中断、重跑或从不同旧状态开始

不适用或需调整：

- 数据破坏操作不因脚本可重跑就成为可逆操作
- 多版本共享资源不适合未经兼容验证的同时替换

必要证据：

- 目标状态、当前允许起点和依赖版本
- 安装、升级、中断恢复与卸载要求
- 脚本副作用及环境配置差异

## 3. 操作与取舍

1. 用版本与目标环境参数选择受控配置，尽量复用同一部署过程。
2. 先验证前提；不满足时明确失败而不是留下半安装状态。需要恢复基线时保存恢复所需证据。
3. 对重复执行、部分完成后继续及已安装版本升级分别规定结果；数据迁移单独处理兼容和恢复。
4. 完成后运行冒烟检查，至少确认进程或入口、必要依赖连接和关键最小路径。

- 重建基线有可预测性但可能造成停机；组件增量更新需验证组合与升级路径
- 统一脚本减少漂移，但环境专属约束仍应显式建模

## 4. 验证与反例

- 相同目标重复部署能得到规定状态或明确可处理错误
- 中断后的恢复路径经过允许环境验证
- 部署成功信号包含冒烟结果，不能仅为命令退出零

反例：第一次部署已创建资源，第二次因“资源已存在”退出，后续配置从未完成，系统处于混合版本。
