## 1. 判断问题

故障之后怎样降低复发概率或影响？

## 2. 条件与证据

适用：

- 达到团队复盘标准的事件或经授权的故障分析

不适用或需调整：

- 普通局部问题无需完整事故复盘；按风险记录必要改进

必要证据：

- 事实时间线、用户影响、证据与信息缺口
- 响应者当时可获得的信息和系统限制
- 候选改进、负责人和完成检查

## 3. 操作与取舍

1. 分开记录已知事实、推断与待核实原因，不把最后操作人员当作根因。
2. 分析触发条件、促成因素、检测与缓解为何成功或失效。
3. 优先选择能减少发生概率、影响范围或恢复时间的具体措施，给出责任与验证。
4. 按改进结果复查而非仅按报告完成结项；复盘内容的共享遵守授权。

- 复盘消耗团队时间，触发标准应与影响匹配。
- 无责文化不是消除责任，改进事项仍需负责人和验收。

## 4. 验证与反例

- 结论可回到证据，未知部分保持未知
- 措施对应已识别风险且有可检查结果
- 跟进能确认措施实际落地并评估效果

反例：结论只有“人员加强注意并重写整个系统”，没有明确失效机制或能检验的改进行动。
