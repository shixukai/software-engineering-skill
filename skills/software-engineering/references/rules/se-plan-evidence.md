## 1. 判断问题

这个日期是目标、承诺，还是当前证据支持的预测？

## 2. 条件与证据

适用：

- 计划、估算、评审里程碑或解释进度偏差
- 跨团队或环境依赖可能改变完成日期

不适用或需调整：

- 不按历史书籍的编码/测试比例直接分配当前项目工期
- 没有数据时不能给出伪精确日期或把工时累计当成完成百分比

必要证据：

- 范围、完成条件、分解任务及依赖
- 可用人员技能、外部等待与集成验证工作
- 已完成结果、未决假设与估算依据

## 3. 操作与取舍

1. 区分目标日期、当前预测和承诺条件；把编码以外的澄清、集成、测试、部署与外部等待纳入计划。
2. 按依赖关系识别不可并行部分和关键链路；对不确定任务给出范围及假设，优先用短探索消除关键未知。
3. 把里程碑写成可展示、可验收的完成事件，不用“差不多完成”或主观百分比。
4. 出现偏差时更新预测及下游影响，比较范围、顺序、资源、日期的可行调整；保护必要质量条件。

- 细化提高可见性但有维护成本；计划粒度应支持下一次决策
- 范围估计不保证日期，明确假设有助于及时重估

## 4. 验证与反例

- 完成事件有证据而不只看投入时间
- 关键依赖、等待和验收工作没有隐藏
- 预测变化及其假设可向受影响方解释

反例：需求与外部接口未确定，却把人员数乘以月份当作可线性分配的容量，并宣称所有任务能在同一天收尾。
