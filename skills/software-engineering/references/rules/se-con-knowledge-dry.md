## 1. 判断问题

这些相似实现是否表达同一条需要共同变化的知识？

## 2. 条件与证据

适用：

- 同一规则、结构或推导结果需要在多处同步维护

不适用或需调整：

- 只是代码外观相似而业务含义和变化原因不同
- 跨越独立所有权建立共享依赖的成本更高

必要证据：

- 每份表示的权威来源与维护者
- 共同变化的原因
- 生成、计算或缓存的更新路径

## 3. 操作与取舍

1. 确认重复的是知识还是语法；先找哪处应为权威表示
2. 能计算就从权威数据计算；多格式输出可由同一输入持续生成
3. 确需缓存时把派生值与失效逻辑封装在同一边界
4. 以真实更新路径检验每份派生表示能否同步

- 共享抽象可能把本应独立的业务耦合起来
- 缓存换取速度，但引入失效与一致性责任
- 生成器也有维护成本，不能只做一次转换后手改产物

## 4. 验证与反例

- 改变权威值后派生结果一致
- 没有要求维护者记住手工更新多个副本
- 缓存更新、重复读取和边界输入覆盖适当

反例：两个独立业务流程各有相同的一行加法，不代表应共享业务函数；缓存长度却不在端点更新时失效，会制造另一份不一致事实。
