## 1. 判断问题

何时继续、暂停或恢复服务，由谁判断？

## 2. 条件与证据

适用：

- 准备发布方案、迁移或部署评审
- 需要选择一次性切换、分批、蓝绿或金丝雀策略

不适用或需调整：

- 不能从“可以自动部署”推断已获生产执行授权
- 无需高可用的小工具不默认引入双环境或复杂流量控制

必要证据：

- 发布范围、候选制品及验证证据
- 可用性目标、允许停机和损失边界
- 责任人、依赖方、观测信号、恢复资源与数据变化

## 3. 操作与取舍

1. 根据失败后果和系统约束选择发布方式，列执行顺序、责任和前提；保持计划与实际自动化一致。
2. 定义发布后冒烟、关键行为和运行指标的观察期，以及具体暂停、继续和回退触发条件。
3. 核实旧制品、配置和数据恢复能力；演练允许范围内的恢复过程并记录耗时与未解决风险。
4. 有共享状态或外部系统联动时验证混合版本兼容；不能简单切回时，事先说明前向修复、只读或人工补偿条件。
5. 对生产等受控环境，向有权决策者提供可审查的候选、证据和剩余风险后，遵守任务既有授权。

- 金丝雀减小首次暴露范围却需要代表性流量、可靠观测和多版本兼容
- 蓝绿便于切换但增加资源成本；切流不能自动逆转新写入或外部副作用

## 4. 验证与反例

- 计划包含首次安装、升级、观察、失败恢复和必要数据处理
- 恢复演练证明实际允许的恢复范围，未演练项明确
- 候选就绪、批准发布、已发布三个状态可区分

反例：只保存旧镜像却删除了旧版本需要的数据库字段，故障后重新部署旧镜像仍不能恢复服务。
