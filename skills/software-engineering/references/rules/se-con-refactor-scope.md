## 1. 判断问题

现在重构的收益是否值得本次扩大改动？

## 2. 条件与证据

适用：

- 结构妨碍当前功能或缺陷修复
- 反复触及的区域持续增加理解成本

不适用或需调整：

- 不需要改动或理解的隔离旧代码
- 大规模重构收益不明确且阻塞很小的交付

必要证据：

- 当前目标和结构障碍
- 预计触达频率与未来迁移难度
- 最小局部改动方案

## 3. 操作与取舍

1. 先说明重构怎样降低本次修改风险或成本
2. 优先预备性小改动；长期改造按保持可运行的小步计划推进
3. 无关或成本较大的清理独立记录，避免夹带
4. 只在收益与任务范围相符时继续，不以整洁的道德要求替代工程判断

- 不重构可能积累维护负担
- 过度重构扩大测试、评审和兼容成本；取舍需项目证据

## 4. 验证与反例

- 每项改动能连回已说明的目标
- 系统在中间步骤可运行
- 未执行的改进明确为建议而非已完成

反例：仅为统一个人风格而重写一个稳定且本任务不触及的模块，不能由“让营地更干净”自动获得正当性。
