## 1. 判断问题

这个改动修掉了故障机制，还是只压住一种症状？

## 2. 条件与证据

适用：

- 已有可检验的故障原因，需要实施或评估修复

不适用或需调整：

- 只有偶然成功的一次试改
- 应急缓解尚未证实根因，却准备报告永久修复

必要证据：

- 故障机制与相关调用上下文
- 能暴露缺陷的用例
- 修复影响、回退点及相邻行为

## 3. 操作与取舍

1. 先确认诊断能排除重要竞争解释
2. 保存可回退基线，一次只作一个有理由的改动
3. 重跑原触发用例与不应受影响的邻近条件，补能暴露旧缺陷的回归测试
4. 检查受影响区域的同类错误；缓解措施和根因修复分别说明

- 局部修补快但可能遗漏机制的其他表现
- 定向检查同类错误有价值，不能扩展为无边界全库整理

## 4. 验证与反例

- 旧行为在修复前可被用例识别，修复后符合要求
- 相邻条件和必要回归通过
- 临时诊断改动与不必要的特殊分支已清理

反例：为某个对象硬编码一个补偿值可以让一次输出正确，却没有修复未初始化状态造成的后续随机结果。
