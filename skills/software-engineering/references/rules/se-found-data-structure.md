## 1. 判断问题

所选表示是否维护业务关系并支持主要操作？

## 2. 条件与证据

适用：

- 集合、索引、队列、图或缓存的表示选择
- 数据结构变化影响排序、去重或访问成本

不适用或需调整：

- 只有字段命名调整且表示语义不变

必要证据：

- 操作频率和规模
- 身份、顺序、重复、修改及所有权约定

## 3. 操作与取舍

1. 列出需要支持的查找、遍历、插入、删除和排序，说明哪一项主导成本。
2. 明确相等与身份、顺序稳定性、重复元素和缺失值的含义；结构的创建及每种修改都必须保持这些约定。
3. 比较简单顺序表示、索引和树/图等必要候选的时间、空间与更新代价；依赖排序、哈希或平衡条件时核实库实现的真实前提。
4. 用空集、单元素、重复/碰撞、边界修改和典型遍历核对契约；图结构同时检查环、不可达节点和遍历终止。

- 索引加速读但增加写放大、同步和内存成本
- 更通用的数据结构增加维护与理解成本

## 4. 验证与反例

- 修改前后不变量保持
- 行为与复杂度预期分别验证，不将性能改善作为正确性证据

反例：需要保留输入顺序和重复项的记录被放进集合，查找虽更快却改变了行为。
