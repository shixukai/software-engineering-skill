## 1. 判断问题

这个测试通过时，究竟证明了什么？

## 2. 条件与证据

适用：

- 新增行为、缺陷修复或契约验收需要可复核的正确性判断

不适用或需调整：

- 需求仍有关键歧义时，不能把当前实现输出直接批准为正确答案
- 仅做格式或无行为影响的低风险修改时，不机械新增测试

必要证据：

- 需求或契约中决定结果的条件
- 初始状态、触发输入、可观察输出及副作用
- 预期值的推导来源与仍未确认的假设

## 3. 操作与取舍

1. 用领域语言写明给定状态、操作和应有结果；先确定断言所代表的语义，再补建立状态的步骤。
2. 把正常、边界、失败与不允许的副作用分开列为测试条件；选择可辨别参数交换、遗漏和错误分支的数据。
3. 预期值来自契约、可独立核算的简单例子或已确认的参考行为；避免调用被测实现自身计算期望值。没有可靠依据时标为探索或行为记录，提出待确认问题。
4. 新增尚未实现的行为或修复已有缺陷时，先确认检查能以预期原因失败，再验证实现或修复后通过。为已有正确行为补回归测试时，允许首次通过，仍须独立推导预期、确认检查实际执行，并用能区分相关错误的输入与断言核对错误敏感性；不得仅为制造失败破坏正确的生产实现。验收测试只证明其覆盖的场景，不能替代需求是否有价值的反馈。

- 显式推导提高可审查性，但复杂算法可能需要独立参考实现或性质验证；这些需另有依据
- 先写断言是一种澄清方法，不是强制每个测试按同一编辑顺序书写

## 4. 验证与反例

- 读者能从测试数据和契约解释期望结果
- 失败原因指向要保护的行为，而非未安装依赖或错误夹具
- 断言包含本场景关键结果与必要的负面约束

反例：把函数当前返回值复制进快照，即使存在业务错误也会通过；它只能记录现状，不能证明期望正确。
