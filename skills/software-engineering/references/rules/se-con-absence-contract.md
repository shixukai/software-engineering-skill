## 1. 判断问题

这个空值是在表示没有结果，还是无法取得结果？

## 2. 条件与证据

适用：

- API 返回 null、空集合或特例对象
- 调用方遍布重复空值分支

不适用或需调整：

- 空值有协议含义且不能直接改变
- 用默认对象会把失败伪装成正常业务状态

必要证据：

- 缺失、空集合、错误各自的业务含义
- 现有调用者与兼容要求
- 默认行为是否有效

## 3. 操作与取舍

1. 列明无结果、未知、失败的语义
2. 正常无元素可返回空集合；有效默认行为可用特例对象
3. 必须区分的缺失使用当前语言适当的显式表示，不能与失败合并
4. 改公共契约前检查所有消费者与迁移安排

- 统一正常空结果减少重复分支
- 特例对象或可选类型引入额外概念；选择取决于语义与语言

## 4. 验证与反例

- 调用者能区分需要不同动作的状态
- 空、缺失、失败及既有消费者均有适当验证

反例：没有附件可以用空列表，附件服务失败却不能也返回空列表并声称查询成功。
