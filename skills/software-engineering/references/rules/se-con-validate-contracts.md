## 1. 判断问题

这个条件是可能发生的输入错误，还是代码不应违反的假设？

## 2. 条件与证据

适用：

- 边界输入或内部不变式需要检查
- 增加防御性代码

不适用或需调整：

- 重复检查没有可信风险且显著增加复杂度
- 只靠可能被关闭的断言保护外部输入

必要证据：

- 输入信任边界与合法范围
- 断言在当前构建中的行为
- 错误后的业务要求

## 3. 操作与取舍

1. 外部可失败输入用运行期验证和明确错误处理
2. 内部约定用无副作用断言表达前后置条件和不变式
3. 必要的执行动作放在断言外，断言只检查结果
4. 对要求更强恢复能力的边界可同时断言和处理，避免无处不在地重复校验

- 断言帮助暴露编程错误，但不构成用户输入保护
- 额外检查有成本且自身也会出错；部署行为需按工具链核实

## 4. 验证与反例

- 启用和关闭断言时必要行为一致
- 非法外部输入被预期处理
- 可信内部不变式违反时可定位

反例：把实际写入动作放进 assert 表达式，在关闭断言的构建中可能连写入也消失。
